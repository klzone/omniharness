# OmniDesk 上手实测清单（真实模型 · 2026-10-22 版）

> 用途：作者本人在**正式环境**亲手跑一遍，判断这套东西到底能不能用来干活。
> 对齐版本：OD-ARCH-053 / 054 之后的当前构建（原生设置页 + 连接测试）。
> 证据等级：下面的"当前情况"来自**文件事实**（读源码与配置）；每一步的"预期"是设计口径，**只有你实际点完才算验证**。
> 全程只用合成样例、公开资料或你已明确批准的数据。案件材料、线索、未公开调查信息一律不进。

一共 6 步，大约 30 分钟。任何一步不符合预期，就停下来记在最后一张表里，不用硬往下走。

---

## 第 1 步：启动并在原生设置页配好端点（5 分钟）

1. 在仓库根目录运行 `scripts/omnidesk.sh`。Desktop 窗口打开后，左侧 Dock 应显示 5 个业务入口：工作台首页 / 周报与随记 / 文案写作 / 项目跟踪 / 项目与会话。
2. 点顶栏右上角的设置图标，或 Dock 底部的设置入口，进入设置页。**这一页是 OmniDesk 自己的原生页面**，不再内嵌 DSH 界面，从上到下是四块：模型与端点 / 场景声明 / 模型权限 / 关于（高级）。
3. 第一次装、还没配过模型时，首页会出现一张「先去设置里配一个模型」的引导卡，卡上「去设置」直达设置页；配置保存后这张卡自己消失（已配过的不受影响）。
4. 在"模型与端点"里填：服务商标识、显示名称、接口地址、接口协议、默认模型、凭据名；需要新密钥就在"API Key"框里填一次（保存后框会清空，界面不会回显）。
5. 先点「测试连接」，再点「保存模型配置」。测试用的是当前填写的内容，不会保存，也不读你已保存的密钥。
6. 点「刷新端点信息」，确认状态里 provider / 模型 / 类别都读得出来。

**「测试连接」应该看到的三种结果：**

| 你填的情况 | 预期提示 |
| --- | --- |
| 地址根本连不上 | 「连不上 —— could not reach …」 |
| 地址通、但密钥不对 | 「鉴权失败 —— … answered 401 …」 |
| 地址和密钥都对 | 「连接成功，读到 N 个模型。」并在"默认模型"下面多出一个候选下拉 |

有候选下拉时可以直接挑一个模型填进去；下拉只是端点自报的清单，输入框照样能手填。测试失败只说明这次没通，**不会**把你已经保存的配置改掉。

**预期**：四块都在、都能改；连接测试三种情况分得清。

**不算数的情况**：只看到"引擎未就绪"或空白，就当作没通过，别往下走——先把端点配好。

> 当前机器上的实际情况（文件事实，可能随你改配置而变）：旧配置是路由 `agnescn / agnes-3.0-flash`，地址 `https://api.agnes-ai.cn/v1`，属公网。`~/OmniDesk/app/config/omnidesk-model.yml` 存在即优先生效，会盖过 Profile 里写的 `deepseek-v4.1-flash`。这个不一致是设计使然，不是故障。

---

## 第 2 步：开权限（2 分钟）

1. 在设置页的"模型权限"区，按端点类别打开对应开关（公网端点就开"公网"）。
2. 回到首页，看底部状态行：应从"模型权限未开启"变为正常，顶栏不再显示 `ENGINE OFFLINE`。

**预期**：权限按**类别**生效，界面明确写出"内容会发往本机以外的地址"。

**不算数的情况**：权限没开却看到生成结果——那只能是本地模板冒充的，记为缺陷。

---

## 第 3 步：选模型（可选，1 分钟）

首页输入框上方有模型下拉，可切换 provider / model / 思考等级。默认项是「跟随 DSH 设置（推荐）」。

**预期**：切换后宿主会用新路由重启引擎，并提示当前端点与类别。

**注意**：换模型不会替你判断数据该不该发出去；权限仍按类别生效。

---

## 第 4 步：三个场景各跑一单（15 分钟）

每个场景都走同一条链路，操作一样，只是内容不同。**先用合成样例**，确认流程通了再换成你自己的合规内容。

对「周报与随记」「文案写作」「项目跟踪」各做一遍：

1. 点 Dock 上对应入口。
2. 点「载入合成样例」，确认格式被接受（周报是 `日期 | 事项 | 状态` 三列）。
3. 点「生成模型初稿」。第一次会拉起引擎，可能要等几秒；等待期间界面应保持可点，不卡死。
4. 成功后"模型初稿"框里出现可编辑文本，标注"模型生成、未复核"。
5. 中途点一次「取消生成」，确认任务落到"已取消"，**不会**显示成功。

**预期**：失败时明确报错（例如 `endpoint_unconfirmed`），不会用模板文字冒充模型产出。

**不算数的情况**：断网状态下也"生成成功"；或取消之后仍出现完整初稿。

> 这一步就是全项目最核心的验收。三个场景任一跑不通，先把现象记下来，不用继续。

---

## 第 5 步：写确认卡 + 强杀恢复（5 分钟）

**保存要人工确认：**

1. 生成初稿后，勾选"我已人工核对以上内容…"。
2. 点「保存成果」。文件落在 `~/OmniDesk/workspace/artifacts`（按时间戳新建，不覆盖已有文件）。
3. 右栏「成果档案」刷新后能看到它，点开是只读预览。

**模型/定时发起的写入走另一条路：**

1. 设置页打开"定时 AI 复盘"，选「仅一次」，时间设成当前或下一小时。
2. 到点后（前端每 30 秒 tick 一次）先出现**待确认写入**记录，此时成果目录**文件数不变**。
3. 进设置页"数据与日志"卡，点「刷新待确认写入」，看到卡片，写明动作与影响范围。
4. 点「确认写入」，出现回执和真实落盘路径。

**强杀恢复：**

1. 在对话里发一条消息，等它回完。
2. 用系统监视器或 `kill -9` 直接杀掉 OmniDesk 进程（不要走菜单正常退出）。
3. 重新启动。对话记录应还在（存在 `~/OmniDesk/app/threads/`），能接着聊。

**预期**：不确认就不落盘；记录 24 小时失效；强杀后历史不丢。

**不算数的情况**：重启后对话全没了——这会推翻"本地持久化"的结论，务必记录。

---

## 第 6 步：改 Profile 声明，验证"重启生效"（5 分钟）

1. 打开 `~/OmniDesk/app/profiles/discipline.yml`。
2. 把 `display_name` 改成你想要的名字；把「文案写作」那一段（`- id: writing` 起 4 行）删掉或注释掉。
3. 存盘，**不要关应用**。等约 5 秒。
4. 界面上应出现一条提示："Profile 声明已在磁盘上修改，重启应用后生效。当前仍按启动时的入口显示。"
5. 此时 Dock 上的「文案写作」**仍然在**（未热重载，符合设计）。
6. 关掉应用再启动：入口消失、左上角品牌名变成你写的名字，提示条也不再出现。
7. 顺手试一次写坏：把 `schema` 值改错，重启后应出现红色提示条说明原因，界面回退到内置 5 个入口，坏文件**原样保留**不被覆盖。

**预期**：改文件不动代码就能改界面；改动需要重启；坏文件不会被悄悄修掉。

**不算数的情况**：改完文件界面立刻变了（说明热重载已生效，与当前实现不符，需记录）；或坏文件被自动改回默认内容。

---

## 第 7 步：记什么（每次 1 分钟）

每单只记一行，**不写正文**：

| 字段 | 例 |
| --- | --- |
| 日期 | 10-21 |
| 场景 | 周报 / 文案 / 项目 |
| 完成？ | 是 / 否 |
| 能用？ | 能直接用 / 改两处可用 / 不可用 |
| 返工类别 | 事实错 / 结构不对 / 太套话 / 格式不合 / 其它 |
| 障碍 | 一句话，例如"生成到一半超时" |
| 耗时（可选） | 粗估区间，如 5–10 分钟 |

真实业务内容、输入正文、输出正文都不要写进使用记录。

---

## 出问题先看哪里

| 现象 | 先查 |
| --- | --- |
| 提交被拒 | 设置页的权限判定；端点是否"无法确认" |
| 生成失败但没文案 | 首页底部状态行；顶栏是否 `ENGINE OFFLINE` |
| 定时没触发 | "定时与提醒"卡的状态摘要；应用是否一直开着（只在运行期触发） |
| 找不到成果 | 右栏「刷新」；「含下级目录」开关 |
| 想核实没写脏数据 | `~/OmniDesk/app/engine-state/pending-writes/` |
| 提示条一直不消失 | 应用没重启；或文件又被改回去了 |

## 不要在正式环境做的事

- 不把案件材料、线索、未公开调查信息贴进任何输入框。
- 不用 `rm` 清理 `~/OmniDesk/app`、`~/OmniDesk/workspace`；要清理先备份。
- 不改 `~/.dsh`、`~/.agents`——这两处不属于 OmniDesk 的数据根。

## 已知限制（当前版本）

- 设置页是 OmniDesk 自己的原生页面；DSH 的完整界面只在"关于（高级）"里留了一个诊断入口，点开会进整个 DSH 应用，日常不用。
- 连接测试只判断"能不能连、密钥对不对、回的像不像模型列表"，不代表这个端点在你所在网络或合规口径下可用。
- Profile 声明只管 Dock 上的业务入口与品牌名，不管 Skill、插件、模型——那些以 DSH 侧配置为唯一权威。
- 声明改动不会热重载，必须重启（界面会提示）。
- 用户报过的"启动卡死"在最近两轮真实窗口测试中未复现，仍未认定修复；再出现请记下当时在做什么。
