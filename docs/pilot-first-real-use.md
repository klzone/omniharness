# OD-ARCH-028 首次真实使用：周报闭环操作提示（2026-10-20）

> 自动化验收已经证明**链路通**（材料 → 模型起草 → 人工编辑 → 确认保存 → 读回，失败/取消不产成果）。
> 这一页是给**你自己用一次**用的：走一遍真实节奏，然后把体验记进产品的「使用记录」。
> 真实体验指标（澄清了几次、改了几轮、顺不顺手）**只能来自你**，自动化跑出来的 0 不算。

## 0. 开始之前

- **材料**：用**公开或合成**的一份材料（推荐先用合成的：一份自己写的周记录 `.md`/`.txt`/`.csv`）。
  真实工作材料是否可用，取决于你**单独取得的书面授权**；本工作台不替你扩大授权范围。
  读材料只认**绝对路径**、单文件、纯文本/表格类型（md/txt/csv/tsv/json/yaml/log）、≤512 KiB。
- **模型权限**：设置里「成果目录与模型权限」→ 确认端点与本机权限。**未开启时提交会被宿主拒绝**，
  界面会直接显示真实原因，不会静默失败。
- **成果目录**：默认写在仓库外的 OmniDesk 数据目录（每次保存新建带时间戳的文件，**不覆盖**已有文件）。

## 1. 五步走完一个周报闭环

1. 左侧 Dock →「**周报与随记**」。
2. 顶部输入框写本周事项（每行 `日期 | 事项 | 状态(done/pending/blocked)`），或点「载入合成样例」先看结构。
   下方「材料目的 / 受众 / 明确要求」是**交给模型时用的**，不是写给人看的公文。
3. 「材料文件」区粘贴你选好的**绝对路径** → 点「读取材料文件」。
   成功后会显示文件名、字节数和 sha256（前 12 位）——这就是来源凭据。
4. 点「**生成模型初稿**」。阶段会显示 running → succeeded；失败会显示真实原因（端点错误、红线命中、
   输出过长等），**不会**给你一段像模像样的假正文。
5. 初稿出现在可编辑文本框里 → **你改完** → 勾上「我已人工核对…」→ 点「保存成果」。
   保存后的文件头会写明「模型来源未复核，已由人工编辑核对」，并附「材料来源（由 OmniDesk 记录，非模型输出）」块。

## 2. 顺手做一次「确定性核对」（可选，但值得）

同一页面的「确定性核对（代码计算）」会算日期是否真实存在、状态计数、逾期判定。
它是**核对**，不是成果，也不会被保存。用它来查模型有没有算错——这正是它存在的意义。

## 3. 把体验记下来（试点评价靠这一步）

页面底部「使用记录（可选）」：勾选「本次流程完成 / 结果可以直接用 / 类似任务还愿意再用」，
选「返工类别 / 障碍 / 耗时」，点「**记录一次**」。

它**只记枚举与粗耗时**，不记输入、输出、标题、路径或会话正文。

本次试点要回答的问题（对应 OD-ARCH-028 的「试点评价」）：

| 指标 | 从哪来 | 备注 |
| --- | --- | --- |
| 执行请求数 | 引擎任务台账 / 本次会话 | 已有自动化计数参考 |

## 4. 边界（自己用也一样）

- 输入框**不是授权入口**：只能放合成、公开或你已明确获准的内容。
- 案件、线索、人物画像一类材料**不进**这个工作台；红线命中会被宿主在提交前拒绝。
- 成果只能来自**模型初稿 + 你的确认**；代码算出来的核对结果不是成果。
- 第一次真实用完之后，建议把「哪里卡住了、哪里不放心」直接说给我，我据此进下一个计划。
