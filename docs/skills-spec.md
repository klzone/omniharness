# OmniDesk Skill 规范（草稿 v1，2026-11-18）

> 状态：草稿，待用户评审修改。来源计划 OD-ARCH-180 阶段 1。
> 适用范围：本仓库 `skills/` 下的全部 Skill；不改现有技能的行为与内容，只约束“怎么写、怎么检查”。

## 1. 一技能一目录、一文件入口

- 路径固定为 `skills/<name>/SKILL.md`，`<name>` 与 frontmatter 的 `name` 一致，用小写字母与连字符。
- 正文不超过约 120 行，用中文写，面向“模型读一遍就能照做”。
- 正文超限，或确有整段模板/素材要随技能分发时，才拆出 `references/`、`assets/`、`examples/`，并在 SKILL.md 里用相对路径指明“什么时候读哪个文件”。没有这种需要就保持单文件，不预建空目录。

## 2. frontmatter 必填三项

| 字段 | 要求 |
|---|---|
| `name` | 技能目录名，唯一 |
| `description` | 一句话。写“遇到什么请求时用我”，而不是“我是什么”。这是模型在技能目录里唯一能看到的信息，触发准不准由它决定 |
| `user-invocable` | true / false。false 的技能不出现在模型自主目录，只由用户手动点名（见 OD-ARCH-174 的目录瘦身口径） |

`description` 写法要求：先写触发场景（用户会怎么说），必要时补一句“不适用的情况”。示例：

> 当用户要求把零散记录整理成正式工作材料、修改已有材料、按模板产出初稿时使用；仅做文件格式转换、与材料内容无关的编辑时不要使用。

## 3. 正文固定六段（段名逐字保留，顺序不变）

### 3.1 用途

一到两句：这个技能只解决哪一类任务。说不清边界的任务不要进去，另立技能或留在场景层。

### 3.2 触发与排除

- 触发：列出 3–5 个用户真实会说的话或任务形态。
- 排除：列出 2–3 个看似相关但**不该**用本技能的情况。
- 这一段是防止误触发的核心；关键词表演式的罗列没有用，要写语义场景。

### 3.3 输入与依据

- 执行需要哪些材料、由谁提供（用户提供 / 宿主汇集 / 知识库检索）。
- 依据的优先顺序：用户明确提供的材料 > 已授权制度与模板 > 知识库历史成果。
- 缺关键信息时怎么办：标注待补，不编造。涉及金额、时间、人名、编号等事实时，必须以材料原文为准。

### 3.4 执行步骤

编号步骤，一步一个动作，模型按序执行；不写“自行判断如何推进”这类交给模型发明的表述。预计 3–8 步；超过 8 步说明任务该拆成场景流程。

### 3.5 输出契约与质量清单

- 输出契约：交付物的格式、必含段落、命名规则、落盘位置（用户确认后由宿主写入）。
- 质量清单：3–6 条**可判定**的检查，例如「每条事实能指回材料出处」「没有材料未支持的结论」「时间线前后一致」「模板要求的各段齐全」。避免“语言通顺”“内容充实”这类不可判定的词。

### 3.6 失败处理

材料缺失、来源冲突、超出技能边界时：停止相关产出，如实说明缺什么、冲突在哪，让用户决定；不硬凑、不越权（不代替用户确认、不自行扩大工具权限）。

## 4. 硬约束（每个技能都适用）

- 不写真实业务材料、案例、人员、凭证；测试与示例只使用合成内容。
- 不重复宿主/场景契约里已有的说明（如“交给我会自动落盘”），技能正文只写本技能要做的判断与步骤。
- 不写工具参数细节（工具 schema 在运行时提供）；需要什么能力用自然语言说明。
- 技能只提出操作要求，权限、审批、落盘一律由宿主执行。

## 5. 验证方式

- `verify_skills_spec_180.py` 断言：frontmatter 三项齐全；六个段名存在且顺序正确；正文 ≤ 约 120 行；不含凭证样式的字符串。
- 触发质量不靠脚本断言，靠真实模型抽测：同一句请求，模型应选用对应技能；相邻技能之间不能互相抢触发（写排除段就是为了这个）。

## 6. 新增与修改流程

1. 用 `skill-creator` 起草 SKILL.md（它按本规范产出模板与边界检查）。
2. 运行 `verify_skills_spec_180.py`，再跑对应场景的 verify 脚本。
3. 真实模型验证一次触发与输出契约，记录到 STATUS。
4. 既有技能按缺口逐个补齐，不做批量重写。

## 7. 示例（合成内容，示意结构）

~~~markdown
---
name: material-writing
description: 当用户要把零散记录整理成正式材料、修改已有材料或按模板产出初稿时使用；仅做格式转换或与材料内容无关的编辑时不要使用。
user-invocable: true
---

# 材料整理

## 1. 用途

把用户提供的原始要点整理成事实准确、结构完整的正式材料初稿。

## 2. 触发与排除

- 触发：整理/起草/修改工作材料；按模板产出初稿；把零散记录合并成一份材料。
- 排除：纯格式转换；与材料内容无关的错别字修复；没有提供任何原始要点的凭空写作。

## 3. 输入与依据

- 需要：写作目的、使用对象、原始要点、目标模板（如有）。
- 依据顺序：用户提供的要点 > 用户指定的模板 > 知识库中的同类历史材料。
- 缺关键事实（时间、对象、数量）时标注待补，不编造。

## 4. 执行步骤

1. 确认写作目的与目标格式。
2. 从要点中提取事实，区分事实、判断与建议。
3. 按模板结构组织段落，事实优先、判断在后。
4. 逐条执行质量清单。
5. 标注待补项与需要用户确认的事项。

## 5. 输出契约与质量清单

- 输出：材料正文 + 待补事项清单；保存位置由宿主按用户确认执行。
- 清单：事实能指回原始要点；无未支持的结论；模板各段齐全；无空泛套话。

## 6. 失败处理

要点缺失、来源冲突或模板不符时，停止相关段落产出，说明缺什么、冲突在哪，由用户决定后续。
~~~

## 8. 与现有技能的关系

现有 10 个技能按本规范逐个审计：只做结构与字段的补齐与修正，不改变已通过验收的行为契约；不合规项列缺口、随迭代处理。
