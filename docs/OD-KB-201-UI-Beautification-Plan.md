# OD-KB-201 知识库页面 UI 美化方案（2026-11-08）

## 一、设计目标

把知识库从“功能齐了，但像若干卡片堆在一起”的状态，整理成一个安静、可扫读的知识运营工作区。

三个判断标准：

1. 一页先看到结论：有多少资料、多少知识、多少待处理、哪里出问题。
2. 人只在需要裁决时停留：审核页看列表和来源对照，资产页看正文和关系。
3. 视觉层级靠版式、字号、留白和细分隔线，不靠更多颜色、更多标签或更多卡片。

非目标：不改变数据链路、审核语义、检索预算；不重做左侧全局 Dock；不引入深色主题或新的持续动画。

## 二、参考结论

| 参考 | 可借鉴的布局规律 | 用在本项目的位置 |
| --- | --- | --- |
| Notion | 侧栏驱动、安静层级、正文阅读宽度、列表 + 属性栏 | 知识资产左列表、正文阅读区、属性折叠栏 |
| Linear | 顶部命令入口、紧凑行列表、主从详情、键盘优先 | 审核中心左队列右详情、全局搜索/操作条 |
| Crunchbase | 指标数字先行、横向数据条、卡片栅格但不过度装饰 | 驾驶舱五格指标、健康卡四格 |
| When I Work | 行内状态点、就地操作、状态分组 | “需要你处理”清单、审核动作区 |

共同规律是：**先给数字与状态，再给解释；列表承担导航，详情承担阅读。**

## 三、整体版式

保留 OmniDesk 现有全局 Dock、顶栏和 Aetheria OS 浅色底。知识库内部统一为一套页面框架：

```
┌ 顶栏：OmniDesk / 知识库             设置 · 状态 ┐
│                                                │
│  [知识驾驶舱] [知识审核 7] [知识资产]   搜索  上传 │
│                                                │
│  页面主体（最大 1440，左右 24–32 留白）           │
│                                                │
└────────────────────────────────────────────────┘
```

- 页签在标题行左侧，右侧只保留一个主操作和一个“更多”入口。
- 统一命令条：搜索、上传原始资料、整理材料、刷新数据，不再散落在页头一排按钮。
- 页面标题与页签同一行；状态用 10–11px 等宽字，避免第二层大标题。
- 内容区采用 12 列网格；卡片圆角 18–20px，细分隔线 1px，阴影只保留很轻的一层。

## 四、页面方案

### 1. 知识驾驶舱

1. 第一行是五格指标带，放在同一块白色玻璃面板里，用竖向细线分隔。
2. 第二行左侧“需要你处理”（约 60%），右侧“AI 最近工作”（约 40%）。
3. 第三行是健康卡：四格横排，每格有数字、短进度轨和一个动作链接。
4. 检索抽检收在健康卡下方，作为一条宽搜索栏 + 最近命中列表，不做独立大卡。

指标带：

| 格 | 主值 | 次信息 | 动作 |
| --- | --- | --- | --- |
| 原始资料 | raw 文件数 | 最近准入时间 | 打开资产 |
| Wiki 条目 | 知识卡数 | 本周新增 | 打开资产 |
| 待审核 | 未决审核项 | 最久等待天数 | 打开审核 |
| 待处理冲突 | 未决链接/异常 | 新增/已清 | 打开冲突队列 |
| AI 任务失败 | 失败数 | 最近一次原因 | 展开任务记录 |

视觉要点：

- 数字 24–26px，等宽字体；标签 11–12px；提示 9.5–10px。
- 指标格之间靠细线，不靠五个阴影卡。
- 有风险时只把对应数字变琥珀/错误色，不整格变色。
- 空态显示“0”和“暂无”，不占用一整块说明文字。

### 2. 知识审核

当前审核项逐条手风琴展开，适合 1–3 条；真实队列达到 7 条后，阅读和定位成本明显变高。建议改成 **左队列 + 右详情**：

- ≥ 1200px：左栏 340–380px，右栏自适应；选中行高亮，详情右栏滚动。
- 顶部页签保留“新知识确认 / 冲突与异常”，显示数量徽标。
- 左行结构：状态点、标题、来源摘要、时间、右侧箭头。
- 右详情：顶部标题 + 状态 + 来源；中部 AI 提取结果或 A/B 来源对照；警告用琥珀色 inline 区；底部固定动作条。
- 冲突行的 A/B 来源做成左右对照卡，路径等宽显示；不再重复两遍“来源 A/B”。
- 窄屏自动上下堆叠：列表在上、详情在下，返回按钮清楚。

### 3. 知识资产

从三栏常驻改成“左列表 + 中正文 + 可折叠检查器”：

- 左列表 280–320px：搜索框、分组（知识卡 / raw / 其他附件）、行内标题与路径。
- 正文 680–760px 最大阅读宽度；标题、路径、元数据行、正文、来源引用按自上而下排列。
- 右检查器默认在 ≥1360px 显示；1280 或更窄时变成滑出抽屉，避免正文被挤窄。
- 检查器包含：关联、反向链接、属性、标签、解析警告、搜索筛选。
- 只读模式默认；`编辑此条` 是显式主按钮。进入编辑器后出现吸底保存条，保存/放弃/冲突处理不离开正文。
- raw 文件继续保留“打开”动作，Markdown 文本保留“查看”动作；两类不混在同一层级里。

### 4. 图谱

- 仍是驾驶舱健康卡的“查看链接索引图”动作，不回到一级页签。
- 打开后是全画面板：顶部浮动返回/缩放/筛选工具，右侧窄栏显示当前节点与图例。
- 背景用浅色点阵/细网格；节点只用三种颜色：默认、孤立、异常。

## 五、视觉令牌

沿用现有 Aetheria 色板，只统一用法：

| 用途 | 建议值 |
| --- | --- |
| 页面背景 | `#FAF8FF`，叠加极淡径向光晕 |
| 主卡面 | `rgba(255,255,255,.72–.82)` |
| 描边 | `rgba(255,255,255,.8)` + 1px 外描边 |
| 正文 | `#131B2E` |
| 次要文字 | `#464555` |
| 弱提示 | `#777587` |
| 主色 | `#3525CD`，悬停 `#4F46E5` |
| 警告 | 琥珀，仅用于风险数字与警告段落 |
| 错误 | `#BA1A1A`，仅用于真实失败/冲突 |
| 大圆角 | 18–20px |
| 控件圆角 | 10–12px |
| 小标签圆角 | 6–8px |
| 阴影 | `0 16px 40px -12px rgba(15,23,42,.04)` |

排版：

- UI 字体 Inter；数字、路径、索引号使用 IBM Plex Mono。
- 页面标题 18–19px / 600；卡标题 12.5–13px / 600；正文 12–13px；辅助 10–11px。
- 行高 1.55–1.7；正文段落不超过 70–76 个中文字符宽度。

动效：

- 只做状态切换：120–180ms 的淡入、滑动、焦点环。
- 不增加持续脉冲、漂浮、全屏 blur。

## 六、实施顺序

1. **视觉基础层**：统一页面框架、命令条、卡片面、分隔线、字号和间距；不改数据和命令。
2. **驾驶舱**：五格指标带、待办/AI 双列、健康四格、检索抽检。
3. **审核中心**：主从布局、队列行、来源对照、固定动作条。
4. **知识资产**：列表分组、正文阅读、检查器折叠、编辑器吸底条。
5. **图谱与边界态**：空态、加载态、错误态、长标题、窄窗、截图验收。

每一步都保持现有命令和测试选择器；需要改动的选择器先补静态验证，再改 UI。

## 七、验收画面

至少截取以下状态：

1. 驾驶舱空态与有数据态。
2. 待审核 7 条、右侧展开第一条的状态。
3. 冲突队列 A/B 来源对照。
4. 知识资产只读态、编辑态和右检查器抽屉态。
5. 1280×820 窄窗与 1440 宽窗。
6. 图谱只读态。

验收标准：

- 驾驶舱一屏内能读出五个核心数字与风险来源。
- 审核页在同一屏内完成“选一条 → 看来源 → 作出裁决”。
- 资产页正文阅读不被右栏挤压；编辑是显式动作。
- 所有空态/错误态都使用真实数据，不生成示意数字。
- 现有功能测试、verify 脚本和用户真实操作路径不回退。
