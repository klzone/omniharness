# OmniDesk 共用任务外壳 v1

- 文档日期：2026-10-16
- 阶段：OmniDesk Discipline 个人自用 MVP（单用户、个人使用、不分发）
- 当前产品边界：[../GOALS.md](../GOALS.md)、[架构决策](decisions.md)；数据处理差距审计：[OmniDesk-Authorization-and-DataFlow-Gap-Audit.md](OmniDesk-Authorization-and-DataFlow-Gap-Audit.md)
- 证据等级约定：`static`（文件/源码事实） · `script`（脚本或进程运行） · `model`（真实模型输出） · `unverified`（未验证）

> 本文只定义**一个**共用的任务外壳，以及**一个**已实现的纵向试点。它不是通用 Agent 平台、不是工作流编辑器、不是任务注册中心，也不引入插件体系。

---

## 1. 这个外壳解决什么问题

个人自用场景下，每个任务其实走同一条骨架：

```text
选任务类型 → 输入 → 确定性步骤 → 解释 → 人工确认 → 本地保存
```

差异只在「规则」，不在「骨架」。所以骨架做成一套共用结构（本节），规则由**任务类型自己的模板/规则文件**表达（§3）。

**明确不做**：

1. 不做通用 Agent 编排、不做多步自主循环；
2. 不做工作流可视化编辑器；
3. 不做任务类型注册中心 / 插件市场；
4. 不为将来可能出现的类型预先建抽象层。

## 2. 共用结构（六个字段）

外壳版本号：`omnidesk-task-shell/1`（`static`，见 [desktop/src-tauri/src/task_shell.rs](../desktop/src-tauri/src/task_shell.rs)）。

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| `task_type` | 任务类型标识 | 只能是被列为 `implemented` 的类型；`reserved` 类型一律拒绝执行 |
| `input` | 输入 | 合成样例，或用户按允许范围填写的内容 |
| `stages` | 阶段 | 固定五段：`input → deterministic → explanation → confirmation → persist` |
| `result` | 结果 | 确定性产物 + 解释文本 + 来源与确认记录 |
| `confirmation` | 人工确认 | 请求必须带 `user_confirmed = true`（缺失字段即反序列化失败）；未确认不得落盘；确认对象是**具体产物**（含统计指纹），不是「点过按钮」 |
| `persist` | 本地保存 | 只写**仓库外**数据目录；同路径不覆盖 |

### 2.1 阶段语义

| 阶段 | 谁执行 | 产出 | 不允许 |
| --- | --- | --- | --- |
| `input` | 用户 / 仓库内合成样例 | 待处理数据 | 直接把手写原文当成计算结果 |
| `deterministic` | **本地确定性代码**（`builtin.analysis.v1`） | 规范化 JSON + SHA-256 指纹 | 让模型产生或修正数值 |
| `explanation` | 模型（现有获准端点）或用户 | 文字解释 | 重算数值；编造数值；引入未提供的数据 |
| `confirmation` | **用户** | 布尔确认 + 可选备注（对象指纹、来源） | 由程序代为确认；用备注替代布尔确认 |
| `persist` | 本地代码 | 仓库外文件 | 写入仓库、覆盖已有文件 |

### 2.2 数值纪律（本外壳最硬的一条）

**统计值只能由确定性代码计算。** 模型拿到的提示词里，统计块是**冻结文本**；模型被要求只解释、不重算。
保存时重新校验「解释所引用的统计块指纹」与「确定性代码产出的指纹」一致，不一致即拒绝保存。

这一条是**代码强制**（`static` + 单元测试），不是提示词约定。

### 2.3 失败与取消

失败、取消、未复核的处理一律**不写成成功**：

- 解释来源只允许 `user` 与 `model_unverified` 两种；产物中留痕；
- 刻意**不提供** `model` 来源：本阶段没有任何能证明「结果确来自已成功终态引擎任务」的机制，此前的 `model` 判定只凭调用方传入的状态字符串，可被伪造，因此移除。可信模型来源须另行设计；
- 统计阶段本地报错 → 不产出指纹，后续阶段无法进行。

### 2.4 统一输入闸门

`analyze_input()`（分析）、`build_explanation_prompt()`（提示词）、`save_artifact()`（保存）**共用同一道启发式闸门**：命中红线扫描即不产出统计结果、不产出提示词、不允许保存。

该扫描是**启发式**，只降低误贴概率，**不构成合规判断**，也不代表获得授权。它无法识别身份、岗位或工作细节；准入责任仍在使用者与授权文件。

## 3. 任务类型清单（当前只有一个已实现）

`static`：清单来自 `task_shell.rs` 的 `task_types()`。

| `task_type` | 标题 | 状态 | 数据范围 | 规则来源 |
| --- | --- | --- | --- | --- |
| `desensitized_analysis` | 脱敏数据分析与生态研判 | **implemented** | 仅合成 / 公开 / 经明确批准的数据 | [templates/analysis/explanation-rules.md](../templates/analysis/explanation-rules.md) |
| `weekly_report` | 周报 | reserved（未实现） | — | — |
| `material_writing` | 通用材料撰写 | reserved（未实现） | — | — |
| `project_management` | 项目管理 | reserved（未实现） | — | — |

> `reserved` 只有**名字和边界**，没有实现，也没有被批准的真实材料准入状态。列在这里是为了避免将来重新发明骨架，**不是**承诺能力。
> 其中「材料撰写」在 DSH Skill 层面另有一条已验收的链路（`skills/material-writing/`），但那是运行在隔离 DSH 内的技能流程，**不**接入本外壳，也**不**因此获得真实材料授权。

### 3.1 为什么先选「脱敏数据分析与生态研判」

1. 它是用户答复里**唯一**被点名的允许用途（见审计 §1.1 原文）；
2. 它的确定性部分可以完全本地完成，不依赖模型，因此**没有模型也能跑通并留证**；
3. 数值由代码算，天然可复现，最容易被证伪。

## 4. 已实现纵向试点的完整数据流

```text
① 载入合成样例或填写数据（仓库内 fixture 或用户输入）
        │  红线关键词扫描（启发式，见 §5）
        ▼
② 确定性统计（Rust 本地代码，不联网、不调用模型）
        │  → 规范化 JSON + SHA-256 指纹
        ▼
③ 解释
        │  模型路径：把「冻结的统计块」原样写进提示词 → 现有获准端点
        │  手写路径：用户自己写，不经过模型
        ▼
④ 人工确认（用户可修改解释文本；确认后才可保存）
        │  保存前复核：指纹一致 + 来源可复核
        ▼
⑤ 保存到仓库外数据目录（默认 ~/YvanAI/projects/Omnidesk/analysis/）
```

各阶段的资产归属：

| 资产 | 唯一权威源 | 运行时去向 | 加载方式 | 失败时行为 |
| --- | --- | --- | --- | --- |
| 外壳定义 | `desktop/src-tauri/src/task_shell.rs` | 编译进桌面宿主 | 编译期 `include_str!` / 常量 | 构建期失败 |
| 合成样例 | `samples/analysis/*.csv` | 编译进桌面宿主 | 编译期 `include_str!` | 构建期失败 |
| 解释规则 | `templates/analysis/explanation-rules.md` | 编译进桌面宿主 | 编译期 `include_str!` | 构建期失败 |
| 产物 | — | `~/YvanAI/projects/Omnidesk/analysis/` | 运行时写入（仓库外） | 目标已存在则拒绝覆盖 |
| 使用记录 | — | `<app root>/logs/usage.jsonl` | 运行时追加（仓库外，不含正文） | 写失败只报错，不影响产物 |

> 三类资产都用**编译期嵌入**而不是运行时读仓库路径：避免「模型看到路径文字就等于读到了文件」这类假象，也避免运行时被仓库外文件替换。

## 5. 数据边界的真实强度（不得夸大）

| 边界 | 实现方式 | 真实强度 |
| --- | --- | --- |
| 产物不落仓库 | `local_data_root()` 拒绝仓库内路径与 `~/.dsh`、`~/.agents`、`~/.codex`、`deepseek-harness` 片段 | 代码强制（`static` + 测试） |
| 不覆盖已有文件 | `save_artifact()` 目标存在即返回错误 | 代码强制（`static` + 测试） |
| 使用记录不含输入输出 | 记录结构只有枚举与布尔，无自由文本字段 | 代码强制（`static` + 测试） |
| 模型不得重算数值 | 提示词冻结统计块 + 保存前指纹校验 | 指纹校验为代码强制；「模型是否守规矩」为提示词级，**未验证** |
| 拒绝案件类内容 | **启发式关键词扫描**（`red_line_scan`） | **仅启发式**：命中即拒绝，漏检不报。**不是**合规控制，也**不能**替代授权 |

> **红线扫描不是合规保证。** 它只是降低误贴概率。真实工作材料能否进入本系统，取决于[审计文档](OmniDesk-Authorization-and-DataFlow-Gap-Audit.md) §3 的逐项书面授权，与本扫描无关。

## 6. 与既有层次的关系

```text
OmniDesk 自有 UI（React/TS）
      │  IPC-1（Tauri 命令/事件）
Rust 宿主 —— 任务外壳 + 确定性统计 + 落盘边界
      │  IPC-2（stdio JSON-RPC）
Python 引擎（omnidesk_engine）
      │  ACP v1
DSH CLI（隔离 Profile）→ 现有获准端点
```

- 确定性统计**不经过**引擎：它是本地代码，因此引擎不可用时该阶段照常可用；
- 解释阶段才用到引擎，且只把统计块当**输入文本**，不把引擎当计算器；
- 外壳不向 UI 暴露任何 ACP / DSH 内部字段。

## 7. 未实现与未确认项（必须与实现分开列）

**未实现**：周报、通用材料撰写、完整项目管理、会议整理、文档审查接入本外壳、检索接入本外壳、任何 GUI 之外的平台能力。

**未确认**（状态只能由用户提供的书面授权文件改写，见审计 §3）：数据/材料、模型/服务商、个人设备、工具、运行环境。

**未验证**：模型在上述提示词约束下是否真的不重算数值（需真实模型输出才能判定）；跨平台；多用户。
