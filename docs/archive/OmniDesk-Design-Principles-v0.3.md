## 一、项目定位

### 项目名称
OmniDesk

### 当前产品
OmniDesk Discipline

### 产品定位
> 面向纪检监察综合履职场景的 AI 工作站。

- 不是通用 AI 助手
- 不是 AI 聊天工具
- 不是自动决策系统

**核心目标：**
利用 AI 显著提升：
1. 材料生产效率；
2. 知识获取效率；
3. 工作经验沉淀效率。

---

## 二、总体架构原则

### 原则 1：先产品，后平台
当前阶段：
- 不建设通用 AI 平台。
- 优先验证：**一个真实用户、一个真实领域、一个真实工作流**。
- **严禁提前开发**：Agent 市场、插件生态、多用户平台、通用工作流引擎。
- 未来演化路线：只有当第二、第三个 Workstation 成熟后，再向上抽象 OmniDesk Core。

---

## 三、技术架构原则

### 原则 2：DSH 作为 Runtime，不作为业务层

```yaml
DSH Runtime
      │
      ▼
OmniDesk Profile
      │
      ▼
Workstation
      │
      ▼
Skills
      │
      ▼
Local Data
```

**绝对禁止修改：**
- DSH 核心代码；
- DSH 运行机制；
- DSH 升级逻辑。

**当前 DSH 验证阶段的配置定制通过：**
- Profile 配置补丁；
- Skill 声明；
- 外部配置文件；
- 外部数据目录。

进入独立桌面产品阶段后，OmniDesk 自有的界面、工作流与应用服务在 DSH 之外实现，不受上述 DSH 配置定制清单限制；仍不得修改 DSH Runtime，也不得把用户数据或领域业务逻辑塞入 DSH 私有实现。DSH 仅通过经验证的适配边界提供执行能力。阶段转换条件见产品路线图。

## 四、核心概念定义

### 1. Workstation (工作站)
定义：一个具体业务领域的工作环境。
例如：`workstations/discipline/`
包含：
```
discipline/
├── profile.yaml
├── skills/
├── knowledge/
├── templates/
└── memory/
```
Workstation 负责：领域配置、技能组合、数据目录映射。

### 2. Skill (技能)
定义：单一、可复用的专业能力。
特点：无状态、单一职责、不保存业务数据。
例如：`material-writing`、`knowledge-search`、`document-review`
Skill 负责：“怎么做”。

### 3. Agent (智能体)
当前阶段弱化。
定义：多个 Skill 的任务组合。
当前策略：不主动开发复杂 Agent，仅在出现多步骤固定业务流时再做组合封装。

## 五、数据设计原则

### 原则 3：数据资产独立于 AI 运行环境
AI 模型与运行工具会变，业务与个人资产必须长期存在。
统一外部数据中枢：
```
~/YvanAI/          # 外部数据中枢（本原则所指的权威数据目录）
├── knowledge/
├── memory/
├── projects/
├── templates/
└── backups/
```
（`~/OmniDesk/` 是**隔离运行根**，只放运行时副本，不存个人知识资产；两者职责不混用。与 [下一阶段简报](OmniDesk-Next-Phase-Brief.md) §1.2、[知识入库与脱敏规则](OmniDesk-Knowledge-Ingestion-and-Desensitization-Policy.md) 一致。）

### 数据分级保护原则
- **一级（公开数据）**：法规公开文件、通用知识。允许云端模型处理。
- **二级（内部资料）**：内部制度、工作材料。优先本地模型或合规专有模型。
- **三级（敏感资料）**：案件线索、未公开调查材料。**绝对禁止进入个人 AI 系统**。

## 六、OmniDesk Discipline v0.1 功能范围

### 第一优先级（P0）
1. **Skill 1：材料写作助手**
   - 目标：提升纪检材料生产效率（工作总结、汇报材料、调研报告、交流发言、理论学习心得）。
   - 流程：素材输入 → 模板选择 → 结构生成 → 初稿生成 → 人工修改 → 模板沉淀。
   - 核心资产：不仅是文本，更是个人写作方法库与套路模板。
2. **Skill 2：知识库助手**
   - 目标：实现可靠知识查询。
   - 强约束：所有回答必须包含：**答案 + 原文引用 + 来源文件 + 具体位置**。严禁无来源脑补。

### 第二优先级（P1）
3. **Skill 3：会议整理助手**
   - 输入：会议记录文本、初转录文本。
   - 输出：会议纪要、任务清单。
   - 未来扩展：连接 V2T 语音处理管道。

## 七、暂不实现功能清单（明确禁止）
1. 自动纪律判断（高风险）
2. 案件审理 Agent（未来仅考虑文书格式检查）
3. 监督检查 Agent（涉及敏感数据）
4. OmniDesk Core 通用抽象（过度设计）
5. Agent Registry / Marketplace（过度设计）
6. **阶段性历史约束，已更新**：原计划直接复用 DSH 桌面/Web UI，现改为最终建设 OmniDesk 自有桌面应用；当前仍不得一次性铺开完整 GUI，按产品路线图先验证工作流与引擎边界。

## 八、版本升级原则（Golden Tasks 守门）
DSH 升级必须通过基线验证。
在 `tests/golden_tasks/` 保存 20-40 个**基准任务**，用于底座升级的回归守门。
任务素材只能是以下三类之一：**合成虚构数据**、**许可范围内的公开资料**、**经书面授权可使用且已脱敏的数据**。
在未取得单位书面授权前，**不得**把真实工作材料、内部文件或任何三级敏感数据编入基准任务；
此时基准任务只能验证**技术与评测流程**是否走通，**不得**据此宣称真实业务收益或真实场景准确率。
授权门槛、逐项授权状态、价值评测与产品化门槛见 [产品目标与架构路线图](OmniDesk-Product-and-Architecture-Roadmap.md) 与 [价值评测协议](../OmniDesk-Value-Evaluation-Protocol.md)。
任何底座升级前，必须跑通：
- Profile 加载测试
- Skill 调度测试
- 文件读取与上下文加载测试
- 输出格式与引用准度测试
- 数据保存与备份测试

## 九、成功度量标准（Discipline v0.1）
1. 材料生产耗时降低 ≥ 20%
2. 知识查询可靠性：引用准确率 ≥ 90%
3. 形成个人持续积累的模版与知识资产

> **口径说明（2026-10-16）**：以上是**产品化**方向的成功度量，**不是作者个人自用的开始使用前置条件**。
> 个人自用先按路线图「阶段 2.6」推进：**不以净节省率 > 20% 作为开始使用的门槛**，使用中先收集低负担的体验与返工记录。
> 度量本身仍须按 [价值评测协议](../OmniDesk-Value-Evaluation-Protocol.md) 计算，且基准任务只能使用合成、公开或经明确批准的数据。
> 逐项授权状态见 [产品目标与架构路线图](OmniDesk-Product-and-Architecture-Roadmap.md) 阶段 2.5。
