# 借鉴研究：Cherry Studio 与灵犀工作台（2026-10-21，ARCHITECT）

> 用途：为 OmniDesk 功能完善提供对标参考。研究方式：灵犀读其 GitHub 仓库 README 与源码说明；Cherry Studio 读官方文档与功能页。均为桌面/自托管 AI 工作台，与本产品形态最接近的两个免费项目。

## 结论
通用对话、模型管理、知识库问答是红海，自研追不上免费成品；差异化仍在本产品的场景工作流（周报/材料/监督项目）+ 成果归档 + 权限治理。两家可借鉴的是交互与治理机制，不是功能清单。

## 可借鉴机制（已按用户指示挑选四项立项 OD-ARCH-046）
1. **写确认制**（灵犀）：模型发起的写操作不直接执行，生成确认卡片，用户点击才落库；宿主侧强制，不靠提示词。
2. **自动降级**（灵犀）：模型不可用/超时/未配置时自动退回确定性结果并明示原因，不装死；但内容生成类不得用模板冒充模型产出（数据诚实红线）。
3. **定时/心跳二分**（Cherry Studio）：定时任务=定点干明确的事（如周一 9 点生成周报复盘）；心跳=定期巡检触发提醒（如拖延/超期扫描）。本产品公告栏两种都需要。
4. **Agent 式设置页**（Cherry Studio）：设置按关注点分卡片（模型端点/权限/定时/成果目录/数据），每卡显示当前状态与主操作，用户看得懂配得动。

## 暂不借鉴
- 灵犀的多用户协作/邀请/角色体系（本产品单用户优先）。
- Cherry 的内置浏览器/绘图等大而全工具面。
- 灵犀的每日调用上限（本轮用户未选，后续需要再立项）。
- 两者均无"场景即预设+成果档案+分区合规"层，此为本产品差异化，不可被带偏成通用工作台。

## 对标提醒
灵犀的"定时周报+逾期扫描"与本产品公告栏设想高度重合且已免费可用——同事试用场景的对照问题是"为什么不用灵犀/Cherry"，答案必须落在场景预设、成果档案、权限治理与体制内材料工作流，而不是"也有对话框"。
