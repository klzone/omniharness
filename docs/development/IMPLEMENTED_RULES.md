# OmniDesk 工程规范：已生效条款汇编（2026-11-05 批准）

> 状态：现行。本文件是五份研究文档（docs/development/*_ANALYSIS.md 与两份规范草案）中"立即采用"项的生效汇编。条款与草案正文一致，生效后草案转为依据文档，不再单独维护"草案"状态。
> 两会话共同义务：GLM 规划会话与 DeepSeek 执行会话从下一次任务起按本文件执行；现行 AGENTS.md 仍然是最高协作规则，本文件是其工程流程细化，不改变角色分工与 Git 保护条款。

## 1. 任务卡模板（GLM 规划会话产出）

以 docs/BUILDER-Task-Instruction-Template.md 为底稿，新增/明确以下字段，全部必填：

    ## 架构契合
    <一行：改哪个既有模块、沿用哪个既有模式、为何不新增抽象层>

    ## 实施步骤
    <顺序步骤，每步一个可检查结果；规定"做什么与验什么"，不规定到代码写法>

    ## 验收命令
    <确切命令 + 预期结果（通过数 / 退出码）；命令取自 §2 命令清单或任务专项 verify 脚本>

    ## 依赖
    <阻塞于哪些任务；与哪些任务可并行>

粒度标准：一个任务 = 一个可独立测试的交付物，一次执行会话可完成，GLM 可单独批准或否决它而不牵连相邻任务。脚手架、配置、文档更新折进受益于它们的任务，不单列。
硬规则：写不出「验收命令」的任务视为未想清，退回规划阶段重新分析。大功能（捆绑多个可独立验收能力）先出能力地图（模块表：OD-ARCH 编号 | 职责 | 依赖 | 构建顺序），经用户确认后逐模块展开。

## 3. 验收证据标准（两会话）

1. **无本轮实跑证据，不得声称完成。**"本轮"指当前会话实际执行并读取输出的命令。
2. 声明→证据对照：声称测试通过须有 0 failed 输出；声称修复须复跑原症状；声称构建通过须有退出码 0。推测性措辞（"应该通过"/"大概率没问题"）视为未验证。
3. 证据落盘：tests/verification/ 对应任务目录；结论标注证据等级（文件事实 / 静态检查 / 脚本运行 / 真实模型输出 / 未验证）。
4. STATUS.md 是执行记录；验收结论只由 GLM 的 REVIEW.md 给出（现行规则，重申）。

## 4. 质量门禁分级（按任务类型，不要求每任务全跑）

| 任务类型 | 必跑 | 按需 |
| --- | --- | --- |
| Rust 逻辑/命令改动 | cargo lib 单测 + 任务专项 verify | cargo --tests、pytest（触及共享层时） |
| 前端 UI 改动 | npm build（含 tsc --noEmit）+ 任务专项 verify | 相关 Rust 单测（触及 IPC 层时） |
| 缺陷修复 | 复现测试（Prove-It）+ 专项 verify + 受影响模块单测 | 全量 lib 单测（跨模块时） |
| 打包/发布改动 | 对应 verify_*.py + 本机构建核对产物结构 | CI 出包核对 |
| 纯文档 | 无 | — |

**降门槛红线（三类，审查必查）：** 不得新增 lint/测试豁免绕过检查；不得跳过或删除既有测试；不得改低验收阈值。执行报告须声明未新增豁免。
安全检查适用条件：触及凭证/数据落盘/网络端点/文件写出的任务必查。架构边界：任务卡"架构契合"行由 GLM 审查核对，runtime/ 零改动为红线。Git 变更审查：每任务报告后 GLM 核对 diff 与允许清单。

## 5. 执行纪律（DeepSeek 执行会话）

1. **入口固定**：获批任务卡 + 交接文件（首个任务时）+ 任务卡点名文件。不从零扫描仓库；架构约束已压缩进任务卡"架构契合"行。
2. **裁决留痕**：任务卡未覆盖的歧义自行决定并在报告记 `Ruling: 决定 — 理由 — 错了代价`，继续执行。
3. **四类停下条件**：不可逆/破坏性操作；安全敏感动作；影响工作区外状态（合并/推送/发布）；计划坏到只能猜。其余歧义裁决后继续。
4. **根因先行**：意外失败即停线，保留错误输出，按序走：复现 → 定位 → 最小化 → 根因 → 修复 → 防复发。未完成根因调查不得提修复方案。同一问题修复两次仍失败 → 停，出报告交回 GLM。
5. **报告固定模板**：基线核对 / 改动文件（对照允许清单）/ 实跑命令与结果 / 裁决记录（无则写"无"）/ 未做与已知限制 / 豁免声明 / 计划偏差。
6. **范围保护**：不做任务未要求的重构、简化、依赖新增；"行为不变的简化"只由计划明确发起的专项任务执行。

## 6. 上下文与交接（两会话）

1. **五层上下文**：常驻规则（AGENTS.md + 本汇编）→ 阶段文档（GOALS/PLANS/decisions）→ 任务点名文件 → 本轮证据 → 会话历史。层 4 只留最近一轮，层 5 默认丢弃。
2. **GLM 维护记忆靠文件**：每阶段结束更新 PLANS 状态行与 REVIEW 结论；新会话从这三文件恢复，不回翻旧聊天。
3. **执行会话会话生命周期**：默认每任务一会话；同任务连续小修可复用；跨任务不复用。出现重复问已答问题、忘记任务卡约束、上下文过大导致截断 → 结束会话新建，入口回到 §5 第 1 条。
4. **交接文件**：按 HANDOFF_TEMPLATE.md 固定字段，约一屏。
5. **Token 纪律**：任务卡点名行号后禁止全仓扫描；工具输出按需截取（失败摘要 + 通过计数）；技能/流程不常驻，按任务卡点名启用，同一流程只保留一份合并规则。
