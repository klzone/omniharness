# OmniDesk 上下文与 Token 管理规范（草案，待用户批准）

> 状态：草案。框架来自 Addy Osmani context-engineering 的五层模型，结合 OmniDesk 双会话现实。获批准后生效。

## 1. 上下文分层（五层模型，映射到现有资产）

| 层 | 内容 | OmniDesk 对应 | 加载时机 |
| --- | --- | --- | --- |
| 1 | 常驻规则 | AGENTS.md + 本规范 + OMNIDESK_ENGINEERING_STANDARD.md | 会话开始自动（已由宿主注入） |
| 2 | 阶段文档 | GOALS.md、PLANS.md、docs/decisions.md | GLM 全读；DeepSeek 只读任务卡点名的段落 |
| 3 | 任务源文件 | 任务卡点名的文件与行号 | 每任务 |
| 4 | 迭代证据 | 本轮测试输出、错误信息 | 每迭代，用完即弃 |
| 5 | 会话历史 | 聊天记录、已完成的任务卡 | 默认丢弃 |

原则：层 4 只保留最近一轮；层 5 不进入交接文件。

## 2. GLM 规划会话

- **整体上下文来源**：GOALS.md（方向）+ PLANS.md（当前计划）+ docs/decisions.md（决策）+ REVIEW.md 尾部（最近审查）。不重读全量 docs/ 与 tests/reports/；需要历史细节时按文件名定位单篇。
- **维护方式**：每阶段结束更新 PLANS.md 状态行与 REVIEW.md 结论，让文件承担记忆，不靠会话历史。新会话从这三个文件恢复，无需回翻旧聊天。
- **给 DeepSeek 的入口**：任务卡 + 交接文件。任务卡自带全部所需上下文（文件、行号、决策依据），使执行会话无需从零扫描仓库。

## 3. DeepSeek 执行会话

### 3.1 最小上下文入口

一个任务卡 + 交接文件（首个任务时）+ 任务卡点名的代码文件。不读 GOALS.md 全文、不读 docs/decisions.md、不读历史 STATUS；架构约束已压缩进任务卡「架构契合」行。

### 3.2 会话结束与新建条件

结束当前会话、新建会话，当出现任一条：

1. 任务卡全部完成且报告已交（默认每任务一会话，最干净）。
2. 上下文明显退化：重复问已答问题、忘记任务卡约束、输出质量下降。
3. 同一任务修复两次仍失败（配合 §2.4 停线规则）。
4. 会话内累计工具输出过大导致响应变慢或被截断。

同一任务的连续小修可复用会话；跨任务不复用。

### 3.3 交接文件（HANDOFF.md，放 tests/verification/evidence 对应任务目录或 docs/，由 GLM 决定位置）

固定字段，总量控制在一屏（约 40 行）：

    # 交接：OD-ARCH-xxx
    阶段：<已完成 / 进行中 / 受阻>
    已完成：<任务编号列表，一行一个>
    未完成：<任务编号 + 卡点一句话>
    修改文件：<路径列表（相对仓库根）>
    测试结果：<命令 + 通过数，本轮实跑>
    Git：<HEAD + dirty 文件数>
    技术决策：<新增决策 + decisions.md 条目号；无则写"无">
    风险：<已知限制与未验证项>
    下阶段入口：<下一个任务卡位置 + 必读文件清单>

不复制聊天历史；不贴长日志；测试结果只留结论行。

## 4. Token 成本控制

1. **重复扫描**：任务卡点名行号后，执行会话禁止全仓 rg / 全目录阅读；GLM 在计划阶段已做过定位。
2. **重复读架构文档**：架构约束进任务卡（一行）；decisions.md 只在 GLM 产生新决策时读相关条目。
3. **工具输出**：测试/构建命令输出按需截取（失败摘要 + 通过计数），不整段粘贴；不开启不必要的 verbose。
4. **历史日志**：STATUS/REVIEW 旧条目是档案，检索用，不整篇进上下文。
5. **必须保留**：任务卡全文、本轮错误原文、验收命令实跑结果、裁决记录——这些省略会直接导致错误决策，不在优化范围。
6. **技能防重复触发**：技能不常驻；任务卡显式点名才启用；同一流程（调试、TDD、验证）在工程规范中只有一份合并规则，技能文档不再各自重复加载。

## 5. 必须保留 vs 可以丢弃

| 必须保留（进文件） | 可以丢弃（不进交接/新会话） |
| --- | --- |
| 获批计划与任务卡 | 已完成任务的实施过程叙述 |
| 决策（decisions.md 条目） | 方案对比的落选分支 |
| 实跑证据（退出码、通过数、证据文件路径） | 完整测试日志正文 |
| 当前风险与未验证项 | 失败尝试的中间输出（结论进 Ruling/风险即可） |
| 允许修改文件清单 | 已关闭任务的报告全文 |
