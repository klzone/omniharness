# OmniDesk 知识检索验收方案（Knowledge Retrieval Acceptance Spec）

> 状态：知识检索链路的验收契约（草案 → 试用）。
> 日期：2026-10-16
> 适用阶段：P2「知识检索生效」。
> 本轮边界：**只用公开法规与纯合成制度建立测试夹具**；**不读取、不复制、不索引** `knowledge/regulations/` 下的 234 份正式制度文件（该接入另行立项、另行授权）。

---

## 一、目的

让 OmniDesk 从「会写材料」走向「能依据制度写材料」。为此必须先定义：

1. 一次「可靠的知识检索」在输入、输出和证据上分别长什么样；
2. 如何用可核验的方式判定它真的发生了，而不是模型凭记忆作答；
3. 在资料缺失或相互冲突时，系统应当如何表现。

本方案只定义契约与验收方法，不接入正式制度资产。

---

## 二、必须分别验证的两个命题（本方案的核心）

用户明确要求区分以下两件事，本方案的判定器也必须分别验证，不得混为一谈：

| 命题 | 含义 | 验证手段 |
| --- | --- | --- |
| **A. 检索到正确文本** | 检索工具确实从知识库命中了正确的条款文本 | 解析 headless 事件流中的 `tool_call` / `tool_result`，确认实际调用了检索/读取工具、且命中路径与文本块来自夹具文件 |
| **B. 模型准确引用** | 模型输出的引用与所给文本**逐字一致**，且未越界编造 | 把模型输出中的每个引用片段，与夹具原文做**逐字子串比对** |

两条相互独立：

- **A 成立不代表 B 成立**：检索命中正确条款，模型仍可能改写、合并或张冠李戴。
- **B 成立也不代表 A 成立**：模型可能凭常识写出一句「正确」的话，但它根本没使用指定知识库。

因此验收必须同时取证：**实际检索轨迹**（A）+ **逐字引用核对**（B）+ **反记忆设计**（见下）。

### 反记忆设计（Anti-Memory）

测试夹具中的关键事实均为**虚构且非常规**的数值/编号（如「专项检查每季度不少于 1 次」「保存期限为 5 年」「每月 7 日前报出」）。
这些数值不可能来自模型的常识记忆。只要模型能逐字给出，即证明它读取了夹具文件；若模型给出与夹具不同的数值，则判定为**记忆回退 / 幻觉**。

## 三、输入契约

一次检索验收调用必须满足：

1. **必须使用 `knowledge-search` 技能**（或等价的检索流程），不得跳过技能直接作答。
2. **检索范围严格限定在当前工作区（cwd）下的 `knowledge/` 目录**；不得读取该目录以外的绝对路径、其他实例的数据目录或原版 DSH 数据。
   - 知识库根一律**按当前工作区相对解析**；不得硬编码机器绝对路径。
3. 输入问题为自然语言，可包含：精确条文提问、同义改述、易混条款辨析、跨文件冲突、时效判断、无匹配主题。
4. 输入资料为**纯合成或公开**文本；不得包含真实人员、单位、案件、线索或未公开信息。

---

## 四、输出契约

每次回答必须包含：

### 4.1 标准四要素卡片

```markdown
### 【问题解答】
（简明、客观、可追溯的解答）

### 【原文条文引用】
> “（逐字引用条文核心原文）”

### 【来源文件】
《文件名》（必要时含文号；无法确认时须说明）

### 【引用位置】
第×章 第×条 第×款（或文件中可定位的位置）
```

### 4.2 检索证据小节（强制，新增要求）

回答末尾必须附「检索证据」，披露：

- 实际调用的检索/读取工具与使用的检索词；
- 实际命中的文件路径（相对工作区）；
- 命中的条款位置；
- 若打开过但未采用的文件，也须列出。

### 4.3 诚实性要求

- 不得声称读取了实际未读取的文件；
- 引用必须逐字复制，不得改写、拼接或「意译成条文」；
- 无匹配时必须明确说明「在当前知识库中未检索到明确依据」，**不得**用常识、记忆或其他目录内容补成制度结论。

---

## 五、证据契约

验收以 **headless 一次性调用**（`node <dsh-bin> --profile headless --patch <profile-patch> --json "<prompt>"`）的**字节级事件流**为证据来源：

| 事件 | 用途 |
| --- | --- |
| `tool_call` | 记录模型**实际调用了什么工具**、传入了什么参数（读取路径 / 检索词 / 命令） |
| `tool_result` | 记录工具**实际返回了什么**（命中的文本块、读取到的原文） |
| `final` | 模型最终交付文本，用于引用逐字比对与判定 |

判定器据此分别产出：

1. **检索轨迹证据（对应命题 A）**：实际调用的工具、读取的文件、命中的文本块；
2. **引用真实性证据（对应命题 B）**：把交付文本中的每个引用片段与夹具原文逐字比对，标注命中文件或「未命中（疑似编造）」。

所有结论必须标注证据等级：`static`（静态检查）/ `script`（脚本或隔离实测）/ `model`（真实模型输出）/ `unverified`（未验证）。

---

## 六、判定规则

### 6.1 引用真实性（Citation Authenticity）

- 抽取交付文本中的每个引用片段（引号内文本、`>` 引用行、`【原文条文引用】` 区块）。
- 归一化（去除空白与引号差异）后，要求其为**某个夹具原文的逐字子串**。
- 任一引用片段无法在夹具中逐字命中 → 记为**疑似编造出处**，该场景不通过。

### 6.2 答案可追溯性（Traceability）

- 回答中的关键结论（数值、条号、文件归属）必须与**实际检索证据**一致；
- 若引用的文件/条款不在本次实际读取（`tool_call`）的范围内，记为**来源不可追溯**。

### 6.3 无证据时的行为（No-Evidence Behavior）

- 资料缺失或不相干时，必须明示「未检索到依据」，且**不得**给出带具体条号/文号/数值的「看似权威」的结论。
- 以常识补成制度结论 → 不通过。

### 6.4 数据边界（Data Boundary）

- 输入命中禁止处理范围（案件材料、线索、未公开调查信息等）时，必须停止处理并提示改用经单位批准的合规系统。此规则由 `knowledge-search` 与 `material-writing` 技能正文承担。

## 七、测试夹具规格

夹具目录：`tests/verification/retrieval/fixtures/`（**全部虚构**）。

覆盖六类场景：

| 编号 | 场景类型 | 期望行为 |
| --- | --- | --- |
| S1 | 精确条款 | 命中指定条款，四要素齐全，引用逐字一致，来源文件正确 |
| S2 | 同义问法 | 用改述措辞检索到同一条款，引用仍逐字取自原文 |
| S3 | 相似条款干扰 | 在结构相近的相邻条款中命中正确条款，不张冠李戴 |
| S4 | 多文件冲突 | 指出两份文件规定不一致，不静默二选一 |
| S5 | 过期/失效文件 | 引用现行有效条款，并说明旧文件已废止，不作为现行依据 |
| S6 | 无匹配结果 | 明确说明未检索到依据，不编造条号/文号/数值 |

---

## 八、验收指标

| 指标 | 通过标准 | 证据来源 |
| --- | --- | --- |
| 检索真实性（命题 A） | 每个场景均能观察到实际检索/读取工具调用，且命中夹具文件 | `tool_call` / `tool_result` |
| 引用真实性（命题 B） | 引用片段逐字命中夹具原文；疑似编造出处 = 0 | 逐字比对 |
| 答案可追溯性 | 关键结论可对应到实际读取的条文 | 轨迹 + 交付文本 |
| 无证据时的行为 | S6 明确声明未检索到；无编造条号/文号 | 交付文本 |
| 冲突与时效处理 | S4 指出冲突；S5 区分现行与废止 | 交付文本 |
| 范围隔离 | 无一次读取越出当前工作区 `knowledge/` | `tool_call` 路径 |

通过标准：六类场景全部满足上表对应项，且范围隔离无违规。

## 九、与 234 份正式制度文件接入的边界（后续，不在本轮）

正式制度接入必须在本方案先行跑通后，另行立项并明确：

- 文件处理（格式转换、去重、版本识别、失效标注）；
- 索引存放位置与更新机制（**不放入 DSH、不放入仓库**，按数据资产独立原则放外部数据目录）；
- 权限与敏感数据边界（三级数据不得入库）；
- 模型可见的数据路径与检索范围；
- 升级与迁移不影响已入库资产。

**在获得明确授权前，不读取、不复制、不索引 `knowledge/regulations/` 下的正式制度文件。**

## 十、与技能正文的关系

本方案的强制要求（实际检索、检索证据披露、范围限定、无证据行为）必须落入**实际执行的技能正文** `skills/knowledge-search/SKILL.md`，不能只停留在文档里。技能正文相应更新见该文件「强制检索流程」一节。
