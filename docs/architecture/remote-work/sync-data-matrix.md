## 2. 三类数据域

1. **中央实时数据**（1-5、9、10）：必须连中央才能读写。离线只能看缓存。
2. **允许离线修改的数据**（6、7 的"新建/编辑"子集）：本地写 + 同步队列，重连后提交；只对纯文件域开放。
3. **不同步域**（8 缓存本体、11、12、13）：本地自理。

## 3. 核心规则

- **单写者原则**：events.jsonl、engine-state、DSH 会话只有中央 Engine 一个写者；多终端永远经 API。
- **乐观并发**：文件域用 etag（内容哈希）+ updated_at；409 时客户端拉取合并后重提。
- **删除统一软删**：业务实体改状态/移目录，不物理删除，避免"删除风暴"同步问题。
- **缓存可弃**：终端缓存全部可删可重建，缓存损坏不影响权威数据。

## 4. 结论

现有"文件优先 + 原子写 + 哈希校验"的存储规范与该矩阵高度契合；不需要 CRDT 或复杂数据库。矩阵中 1-5 项在现有代码里已有全部权威源，缺的只是 API 层与 etag；6-7 项的离线编辑是 Phase 4 内容。
