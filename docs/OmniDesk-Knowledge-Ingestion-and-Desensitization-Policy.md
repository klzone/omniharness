# OmniDesk 知识入库与脱敏规则 v0.1

> 状态：生效（项目宪法级约束，与 `skills/material-writing/SKILL.md` 第〇节数据边界一致）
> 适用：所有向 OmniDesk 知识库（`knowledge/`）导入资料的人与 AI 模型（Codex / Claude / Gemini / GPT 等）
> 制定日期：2026-10-16
> 一句话原则：**入库前先分级，分级为“敏感”的一律不进；进不进由人决定，AI 只执行判断之外的动作。**

---

## 一、目的与适用范围

本规则解决三个问题：

1. 哪些资料**可以**进个人 AI 工作站的 `knowledge/`；
2. 可以进的资料在入库前需要做哪些**脱敏处理**；
3. 每类资料**放在哪个目录**。

适用范围：`knowledge/` 下所有目录，以及通过脚本（如 `scripts/ingest-documents.py`）导入的任何文件。

**不适用**：`~/OmniDesk/runtime/`（运行环境）、`sessions/`（会话）、`~/.dsh`（原版 DSH 数据）。本规则只管知识库。

**准入前提（高于本规则）**：任何**真实工作材料或内部文件**在进入本工作站的 `knowledge/`、`memory/` 或任何对话之前，
必须先取得**单位出具的书面授权**，且授权须**逐项**覆盖：**数据/材料、模型/服务商、工具、个人设备、运行环境**。
**材料授权不能代替模型、工具或环境授权；脱敏本身也不代表获准**（脱敏解决的是“数据是否敏感”，授权解决的是“是否允许使用”）。

未获相应书面授权前，只允许处理**合成数据、许可范围内的公开资料、经明确批准的数据**。
项目当前授权边界与阶段目标见 [GOALS.md](../GOALS.md)；原详细阶段规划已归档，仅作为历史背景，不替代当前授权判断。

---

## 二、数据分级与处置矩阵

沿用单位既有“公开 / 内部 / 敏感”三级口径，与 AI 使用能力挂钩：

| 级别 | 定义 | 能否入库 | 能否交给云模型 | 允许目录 |
| --- | --- | --- | --- | --- |
| **一级 公开** | 已对社会或全行公开发布的法规原文、公开发布的会议精神、公开通报 | 可直接入库 | 可以 | `regulations/` `policies/` `learning-materials/` |
| **二级 内部** | 内部制度、本人原创文稿、脱敏后的经验总结、公开口径宣传素材 | 脱敏后可入库 | 优先本地模型；云模型须单位允许 | `regulations/` `methodology/` `reflections/` `writing-style/` `excellent-cases/` `meeting-materials/` |
| **三级 敏感** | 案件材料、案件线索、未公开调查信息、涉案人员信息、未公开通报、举报内容、涉案财物信息、干部廉政档案 | **一律禁止入库** | 禁止 | 无（应留在单位批准的系统） |

**判定顺序**：先看是不是三级；是三级 → 立即停止，不得以“脱敏后就能用”为由进入；不是三级 → 再看是否满足二级的脱敏要求。

## 三、严禁入库的红线数据（三级）

以下内容**任何形式**都不得进入 `knowledge/`、不得写入 `memory/`、不得贴进本工作站的任何对话：

- 案件材料、案件线索、初核/立案/审查调查过程中的任何文书；
- 尚未定性、尚未公开的举报内容、信访举报件及其办理情况；
- 涉案人员真实姓名、职务、单位、联系方式、亲属关系；
- 涉案财物、账户、资金往来的具体信息；
- 干部廉政档案、党风廉政意见回复的具体意见内容；
- 未公开的通报、领导批示、内部会议纪要中的敏感议题；
- 巡视巡察未公开的问题线索与反馈意见。

**禁止的规避手法**（明确写死，防止自己和 AI 都“想当然”）：

1. 不得以“去掉姓名即可”“自动脱敏”为由把上述数据放进本工作站；
2. 不得把敏感数据改写成“某案”“某件”后当作案例素材；
3. 不得把敏感数据先放进 `excellent-cases/` 再从那里当范文用；
4. 不得以“只是测试一下模型”为由输入真实敏感数据。

一旦发现输入涉及红线：**停止处理该部分内容**，并提示改用单位批准的合规系统。

## 四、可入库资料与来源要求

| 类别 | 示例 | 来源要求 | 目录 |
| --- | --- | --- | --- |
| 法规制度原文 | 党章、纪律处分条例、问责条例、监察法等 | 必须是公开权威版本；写明版本年份 | `regulations/` |
| 上级政策部署 | 中央纪委全会报告、工作要点、专项整治部署 | 公开发布口径 | `policies/` |
| 单位内部制度 | 本行制度汇编、工作指引、实施办法 | 脱敏后入库；**不入 Git** | `regulations/` |
| 个人写作方法 | 风格规则、常用表述、结构模式、避雷清单 | 本人原创或公开来源 | `writing-style/` |
| 优秀范文（脱敏） | 获好评的工作总结、发言、汇报范文 | **必须脱敏**；不含红线数据 | `excellent-cases/` |
| 方法论沉淀 | 政治监督常态化、台账管理、跟踪问效等经验 | 脱敏后可入库 | `methodology/` |
| 本人心得体会与文稿 | 心得体会、发言稿、汇报、宣传稿 | 免脱敏，但**本地保留、不入 Git** | `reflections/` |
| 学习资料 | 学习辅导材料、公开出版物、公开课件 | 公开来源；注明出处 | `learning-materials/` |
| 会议材料 | 公开口径的会议纪要、学习记录 | 脱敏后可入库 | `meeting-materials/` |

**来源可追溯要求**：每份入库资料应能说清“从哪来”。批量导入时由 `scripts/ingest-documents.py` 生成的 `manifest.json` 承担这条记录；手工放入时在对应目录 `README.md` 或文件头部注明来源与日期。

## 五、脱敏操作清单

对判定为“二级内部、需脱敏”的材料，逐项执行：

| 对象 | 处理动作 | 示例 |
| --- | --- | --- |
| 真实人名 | 改为化名或职务代称 | “张三” → “某干部”“A 同志” |
| 真实单位/支行 | 改为泛称 | “XX 支行”“某二级分行”“某单位” |
| 具体金额 | 区间化或比例化 | “涉案 137.6 万元” → “涉案金额较大”或“百万元级” |
| 具体账号/编号 | 删除或替换 | 银行卡号、员工编号一律删除 |
| 具体时间点 | 粗化 | “2021 年 3 月 12 日” → “2021 年 3 月”或“某年某月” |
| 文号 | 公开制度文号保留；内部通知文号保留 | 文号本身是制度身份，如“农银深党纪〔2020〕5 号”可留 |
| 附件中的名单/表 | 先去敏再入库；无法去敏则不入库 | 处分决定附件、人员名单 |
| 图片/截图 | 先遮盖敏感信息；无法遮盖则不入库 | 系统截图中的姓名、账号 |
| 涉密标识 | 见到“秘密/机密/内部资料”等标识，默认不入库 | 直接按三级处理 |

**保守原则**：拿不准是否敏感时，**默认不放行**。宁可少收一份，不可多留一份。

## 六、目录归属映射（“我放哪里”）

```
knowledge/
├── regulations/          法规制度原文（真实业务文件，不入 Git）
├── policies/             上级政策部署
├── methodology/          方法论沉淀
├── writing-style/        本人写作规则（项目资产，入 Git）
├── excellent-cases/      脱敏后的优秀范文（项目资产，入 Git）
├── meeting-materials/    会议材料
├── reflections/          本人心得体会与原创文稿（免脱敏，本地，不入 Git）
│   ├── thoughts/         心得体会
│   ├── speeches/         发言稿、交流研讨材料
│   ├── reports/          工作汇报、情况报告
│   └── news/             新闻稿与宣传素材
└── learning-materials/   学习资料（本地，不入 Git）
```

**心得体会放哪里的明确答案**：放 `knowledge/reflections/thoughts/`。
这类本人原创文稿**不需要脱敏**即可放入，但因为它可能含真实单位与人员姓名，**默认不进入 Git**（`.gitignore` 已排除其内容，仅保留目录说明）。

**如果某篇心得想当作写作参考范文**：先按第五节脱敏，再另存一份到 `knowledge/excellent-cases/`。心得原文留在 `reflections/`，范文副本进 `excellent-cases/`，两者分开。

## 七、审核关卡与记录

每次入库必须经过两道闸：

1. **人工复核（本人）**：确认不是三级数据、脱敏已执行到位；
2. **AI 执行（脚本或 Skill）**：只按规则搬运与转换，**不替人做敏感判断**，遇到疑似敏感内容停止并报告。

入库登记建议记录四项：来源路径 / 入库日期 / 分级 / 脱敏说明。批量导入由 `manifest.json` 自动记录来源路径与时间；手工入库在目录 README 中追加一行。

## 八、非文本格式与特殊文件处理

| 格式 | 说明 | 处理 |
| --- | --- | --- |
| `.wps` | WPS 文字（旧版为 OLE 复合文档，新版可能为 OOXML） | 转为 `.docx`；**原件不动** |
| `.doc` `.docx` | Word | 直接保留复制 |
| `.pdf` | PDF | 直接保留复制 |
| `.et` | WPS 表格 | **不动**（不转换、不复制），如需入库另行处理 |
| `.gd` | 金山专有/加密格式 | **不动**，需在 WPS 中另存为通用格式后再入库 |
| `.ofd` | 国标版式文档（常用于公文） | **不动**，如需文本内容另行转换 |
| `.emmx` | 思维导图 | **不动** |
| `.zip` | 打包压缩 | **不动**，解压内容另行判定后导入 |

**原件保护**：任何导入脚本都**不得修改、移动或删除源文件**；转换产物按原文件夹分类复制到目标目录。

## 九、与 Skill 数据边界的一致性

本规则与 `skills/material-writing/SKILL.md` 第〇节、`skills/document-review/SKILL.md`、`skills/knowledge-search/SKILL.md` 的数据边界**必须一致**。三者冲突时，以**更严格**的一条为准。

特别地：`knowledge-search` 检索到内部制度时，回答仍须遵守“原文引用 + 来源文件 + 位置”的四要素，不得因为“库里有”就默认可以外传。
