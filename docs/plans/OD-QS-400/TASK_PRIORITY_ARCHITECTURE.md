# 任务优先级架构（TASK_PRIORITY_ARCHITECTURE）

> OmniDesk 第二阶段规划文档（OD-QS-4xx）。来源：用户《第二阶段总任务：任务四象限 + 智能排期》方案 + 2026-11-08 已批准裁决。本文件是规划快照，实施与验收状态以 PLANS.md / REVIEW.md 为准。

## 1. 三套机制严格分离

| 机制 | 存储 | 生命周期 |
|---|---|---|
| 任务状态（待确认/待开始/进行中/已完成/已取消/暂停） | Task frontmatter `state` | 用户白名单迁移（第一阶段） |
| 四象限（Q1–Q4 / 待评估） | **不落盘**，读取时派生（仅 quadrant_override 落盘） | 每次读取重算 |
| 排期状态（已建议/已确认/已调整/已取消/已完成） | work/排期/ 独立文件 | 与任务状态解耦（D-071） |

## 2. 重要性评估

- **等级：** 高 / 中 / 低 / 待评估（有限枚举，不引入数值评分）。
- **来源标记：** importance_source ∈ {ai, user, rule}；importance_reason 必填（一句话依据）。
- **AI 建议：** 搭既有提取调用顺车（D-070），候选确认落 Task 时写 source=ai。约束：不得仅因领导提出即判高；无截止日期不判低。
- **用户修正：** task_set_importance（source=user，追加调整记录）；用户值持续生效，AI 不覆盖。

## 3. 紧急性评估（派生）

- compute_urgency(task, now) →（等级：高/中/低/待评估，依据文本）。
- 规则：逾期→高（附逾期天数，但象限仍看重要性，不强制 Q1）；hard due 按工作日节奏分档（阈值常量注明依据，不用固定 24/48h）；target due 降档；due 空时对 hint 封闭模式集（明天/后天/下周X/本月底/下月底/X月X日前）推定日期标「推定」，模式外→待评估（D-075）。
- 时区：使用系统本地时区，不静默换模型服务器时区。

## 4. 四象限分类

- classify_quadrant(task, urgency, now)：两维齐备→按组合归 Q1–Q4；任一维待评估→象限「待评估」，不强行归类；override 非空→返回 override 并标「用户指定」。
- 已完成/已取消→active=false（不出现在待办象限，历史记录保留）；暂停→保留重要性、不排入近期日程。
- 动态变化：象限随紧急性派生实时更新；变化依据由 (urgency 依据, importance 依据) 解释，无需另存历史。

## 5. 用户调整与审计

- task_set_quadrant：设置/清除 override，追加调整记录（时间 + 动作 + 理由）。
- 界面标注「与 AI 建议不一致」提示；用户清除 override 后回到规则派生。
- 任务详情展示：重要性/紧急性/象限 + 双依据 + evaluated_at + is_override。
