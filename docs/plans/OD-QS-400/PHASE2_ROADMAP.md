# 第二阶段路线图与后续衔接（PHASE2_ROADMAP）

> 实施状态以 PLANS.md / REVIEW.md 为准。

## 一、第二阶段内部顺序

1. **基础层（并行起步）：** 401 字段扩展 → 402 紧急性引擎 → 403 象限引擎；同时 404（AI 建议）与 407（排期实体）、406（时间配置）。
2. **IPC 层：** 405（优先级调整）与 409（排期确认流）。
3. **界面层：** 410（四象限页+旧占位替换）与 411（今日/本周计划）可并行；412（详情扩展）收尾。
4. **收口：** 413 全量回归+安全核对。

建议派发节奏（单执行会话一任务）：401 → （402 ∥ 404 ∥ 407，406 可同日） → 403 → （405 ∥ 408） → 409 → （410 ∥ 411） → 412 → 413。

## 二、第三阶段衔接：知识库深度联动

- 任务与排期均为 work/ 下稳定形状文件（frontmatter 固定字段），知识库模块届时**只读引用**，不预建接口、不预建同步机制。
- 预留：任务完成时产生的成果（如某项制度文件）已有归档通道（OD-WR-312 vault_archive），三阶段可复用该入口挂接「任务成果 → 知识卡」流。
- 象限视图的 QuadrantView 结构含双依据文本，可供知识库摘要直接引用，无需二次解析。

## 三、第四阶段衔接：文案写作联动

- 排期条目的 start_at/end_at 与任务的 estimated_minutes 可作为写作任务的时段约束输入；届时按需读取，不预建接口。
- 文案写作产出的发布态成果走既有 archive_artifact_to_vault 通道；任务关联（source_record_id / linked_record_ids）不变。

## 四、明确不做（第二阶段）

不重建任务管理模块；不接外部日历；不做多人协同排班/复杂 KPI/通用平台；不自动改用户已确认安排；不为排期重构数据层；不开发自动任务拆分（仅建议+手动建子任务）。
