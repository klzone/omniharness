# AI 文稿写作架构（OD-WT-600 规划成果一）

> 状态：已批准（2026-11-09 用户裁决：定稿→导出→归档闭环；DOCX 复用 office-docx 技能+textutil 兜底；PDF 走 soffice/打印流；公众号 HTML 宿主渲染；写作任务实体落 work/写作/；归档门禁软引导）。实施状态以 PLANS.md / REVIEW.md 为准。

## 一、实体关系与数据流

```
写作需求（自然语言）──AI 解析──→ WritingTask（work/写作/<writing_id>.md，九态独立）
                                      │
        ┌─────────────────────────────┤ 素材收集（material_query + 知识检索 + 项目概览）
        ▼                             ▼
   素材包（派生视图：selected_material_ids/knowledge_ids + 章节映射）
                                      │ 大纲生成 → 用户确认（outline.md）
                                      ▼
   分章节写作（每章：确认大纲节 + 素材 + 知识 → 章节稿候选 → 用户确认）
                                      │
        ┌─────────────────────────────┼──────────────────┐
        ▼                             ▼                  ▼
   正文.md + versions/        事实核验引擎          引用追溯（citations.jsonl）
                                      │
                                      ▼
                     定稿（用户确认）→ 导出（MD/Word/PDF/公众号 HTML，可多格式多次）
                                      │
                                      ▼
                     归档（MD 进 vault 报告目录）→ 已归档（终态）
                                      └─→ 知识回流（经治理流程，用户确认）
```

## 二、核心原则（方案 §二照录执行）

事实优先（文稿事实必有来源）；素材优先（只调已确认素材）；知识辅助；人工主导（AI 只建议，状态迁移仅用户触发）；过程可追溯（重要事实可定位原始来源）；结构先行（大纲确认后才生成正文）；分段生成（分章节，不全量一次生成）；多轮修改；版本留痕（关键节点快照）；安全优先（继承 gate_user_text + masker + 红线扫描，零新增外发通道）。

## 三、AI 工作流八层（方案 §六）

需求解析 → 素材检索 → 素材组织 → 大纲生成（用户确认门禁）→ 分章节写作 → 交叉审阅 → 人工确认定稿 → 导出归档回流。模型调用照 D-088：宿主组提示词+校验，调用在界面侧，输出进候选暂存，确认后落盘；大纲未确认不得调正文生成（校验拒绝+安全断言）。

## 四、与前三阶段边界

- 素材接口 material_query（509）直接复用，默认已确认素材，无需补齐。
- 归档走 vault_archive 既有通道（MD 进报告目录）；知识回流走既有 knowledge 治理流程，不自动转条目。
- 写作任务与正式任务零耦合（独立实体独立九态）；work/写作/ 不参与定期清理（602 显式排除）。
- Token 消耗引擎不报 usage，只记调用次数与耗时，不估算（GOALS 既有口径）。
