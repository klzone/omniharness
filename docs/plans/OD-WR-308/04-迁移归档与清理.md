# 迁移、归档与清理计划（309–313）

> 状态：尚未实施。309 存量迁移与 313 清理须用户单独授权后才能开工。

## 309 存量周文件一次性迁移

- 输入：既有 library_root/工作记录/ 下的周文件。
- 动作：解析周文件拆条，写 work/工作记录/；校验拆出条数与原文件一致后，把原文件字节不动地移到 work/周文件存档/。
- 失败：整批回滚，不留半迁移状态。
- 幂等：重复执行不重复拆条、不重复归档。
- 验收：cargo lib 覆盖拆条、归档、回滚、幂等。
- 授权：执行前须用户单独确认一次。

- 验收：cargo lib；新增 verify_worklog_unify_305.py。

## 312 报告与成果归档知识库

- archive_report_to_vault：用户确认后把定稿复制进 <vault_root>/报告/，frontmatter 记来源周期；同名同内容幂等，同名不同内容拒绝。
- archive_artifact_to_vault：只允许发布态成果；草稿拒绝。
- 工作记录与未发布草稿永不归档。
- 验收：cargo lib；tsc。

## 313 临时层清理

- 圈定：已归档报告覆盖期的记录 + 完成/取消超过 90 天的任务；draft 与被未完成任务引用的记录永不入选。
- 预览：work_cleanup_preview 零写入。
- 应用：用户确认后移到 work/.trash/，不直接删除。
- 保留期：work/retention.v1.json，默认 90 天。
- 验收：cargo lib；新增 verify_work_cleanup_307.py。
- 授权：执行清理动作前须用户单独确认。

## 顺序与风险

309 → 310 → 311 → 312 → 313。迁移先于切换，切换先于清理；每步保留旧数据只读副本，失败整体回滚。主要风险是迁移损坏：用字节归档 + 条数校验 + 回滚 + 单独授权来控制。
