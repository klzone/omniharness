# 技术架构：工作记录 + 任务

## 分层

- 临时层：$HOME/OmniDesk/work（可由 OD-WR-315 设置覆盖）。工作记录/<record_id>.md、任务/<task_id>.md、.candidates/、.trash/、周文件存档/。
- 知识层：<vault_root>。知识卡、报告/、归档成果；知识库扫描不覆盖临时层。
- 应用数据根：设置、规则、引擎状态、候选归档与日志；不在仓库内。

## 模块职责

| 模块 | 职责 | 依赖 |
| --- | --- | --- |
| worklog_records.rs | 记录 CRUD、frontmatter、列表过滤、删除进回收目录 | sha256 仅用于去重键；task_store 不使用其内部实现 |
| task_store.rs | 任务 CRUD、六状态白名单、进展/状态历史、候选暂存、去重、关联采纳/拒绝 | worklog_records 的原子写入与 id 校验 |
| task_extract.rs | 解析门禁、提示词组装调用、validate_task_payload、落地与失败置状态 | task_store、worklog_records、knowledge_ingest 的 JSON 解析 |
| lib.rs | IPC 命令、工作根解析、红线/掩码闸门、引擎提交 | settings、profile_rules、task_shell、admission |
| engine/omnidesk_engine/task_extract.py | 只组装提示词；无文件读写、无模型调用 | 标准库 |
| WorkRecordPage / WorkRecordLibrary / TaskManager / TaskReviewPanel | 四个视图 | api.ts、types.ts |

## 存储格式

记录 frontmatter：id、title、record_date、created_at、updated_at、category、tags、source、ai_analysis_status、linked_task_ids、draft；正文在围栏后。

任务 frontmatter：id、title、state、created_at、updated_at、source_record_id、source_quote、linked_record_ids、category、due_date、hint；正文分「进展」与「状态历史」两段，条目只追加。

候选：.candidates/<candidate_id>.json；字段含 record_id、source_quote、title、confidence、uncertainty、match_task_id、match_confidence、match_reason、suggested_state、去重键与状态。确认/拒绝/关联后移到 .candidates/已处理/。

## IPC

- 记录：work_record_create / read / update / delete / list。
- 解析：worklog_record_analyze（出提示词）、_apply（校验并暂存）、_failed（置失败）。
- 任务：task_create / read / update / delete / list / transition / append_progress。
- 候选：task_candidate_list / confirm / reject / link / dismiss_match。
- 设置：work_root_info / task_set_working_root。

## 解析链路

1. 宿主读记录，检查 ai_analysis_status 未为 analyzed。
2. 红线扫描与 mask_privacy 再次作用于标题与正文。
3. 宿主取未完成任务摘要（最多 30 条），调用 task_extract.py 组装提示词。
4. 界面提交引擎任务并轮询；宿主不阻塞 UI。
5. 模型结果回填：parse_result_text → RawPayload 严格结构 → 逐条校验 quote、日期、置信度、关联任务、状态建议。
6. 校验通过：stage_candidates 去重暂存，记录置 analyzed。
7. 校验或暂存失败：记录置 failed，正文不动；模型失败由专用 IPC 置 failed。

## 关联采纳

link_candidate：读候选与目标任务 → 追加进展 → 任务 linked_record_ids 加入记录 ID → 记录 linked_task_ids 加入任务 ID → 候选归档为 linked。

## 失败语义与边界

- 文件写入是「临时文件 + fsync + 硬链接/rename」，单文件原子；跨文件不是事务。
- 已解析记录拒绝重复解析；failed 允许重试。
- 关联目标只允许待开始/进行中/暂停；终态任务不能追加进展。
- 引擎协议、runtime/、知识库红线机制均不变。
- 新增依赖为零；Python 只用标准库。

## 测试结构

- cargo lib 单测覆盖存储、校验、失败副作用、三日记事归一任务。
- pytest 覆盖提示词组装与 CLI。
- 四份静态 verify 覆盖页面接线与联动；一份安全静态 verify 覆盖安全断言。
- 真实模型与真实窗口不在自动测试范围。
