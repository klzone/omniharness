# CodeGraph 本机接入与省 token 实测

状态：已安装、已建索引、已做 A/B 实测（2026-10-23）。不属于产品功能，只影响开发协作方式。

## 装在哪

- CLI 装在系统全局：`npm i -g @colbymchenry/codegraph@1.6.2`，路径 `~/.nvm/versions/node/v22.23.2/bin/codegraph`，**不在本仓库内**。
- 索引数据在仓库的 `.codegraph/`（约 15 MB），已加入 `.gitignore`，不进 Git。
- MCP 配置写入 `~/.codex/config.toml` 的 `[mcp_servers.codegraph]`，首次配置前的备份是 `config.toml.bak-odcodegraph`；遥测已关（`CODEGRAPH_TELEMETRY=0`）。
- 生效需要重启 Codex 会话（MCP 只在启动时加载）。当前会话内没有该工具，因此下面的测量走的是同一套 CLI 入口。

## 索引范围（重要）

首次 `codegraph init` 把 `runtime/` 里上游 DSH 源码也扫进去了：8342 个文件、619 MB、索引被中断、大量噪声。已用 `codegraph.json` 排除 `runtime/`、测试证据、`dist/`、`audit/`、`knowledge/`、`memory/`，并降权 `tests/`、`scripts/`。重建后：**128 文件 / 3,918 节点 / 10,848 边 / 14.9 MB**。

`knowledge/` 被排除是刻意的：那里是用户资料，不是代码，不该进代码图。

## 实测（同机、同仓库、2026-10-23）

对照组口径：先用 `rg` 定位，再整篇读相关源文件（这是不用图时的真实做法）；实验组：一次 `codegraph explore`。都按字符数计，字符与 token 近似同比例。

| 场景 | 对照 | 图检索 | 省 |
| --- | --- | --- | --- |
| 取消链路 `cancelTask` 跨 TS + Rust | 96,518 字 / 5 次调用 | 12,735 字 / 1 次 | 87% |
| 规则资产 `profile_rules` 加载与红线扫描 | 162,144 字 / 3 次 | 14,603 字 / 1 次 | 91% |
| 准入闸门 `submission_gate` | 143,166 字 / 2 次 | 15,578 字 / 1 次 | 89% |
| 不知道文件在哪（`privacy_masked` 这类散点问题） | 202,470 字 / 4 次 | 14,279 字 / 1 次 | 93% |
| 单个中等文件（`profile_rules.rs`） | 18,978 字 | 16,021 字 | 16% |
| 单个小文件（`scheduler.rs`） | 12,410 字 | 14,890 字 | **-20%** |

结论：**跨文件、不知道位置的问题省 85–93%**；**本来就只读一两个小文件的问题会倒亏**——图会把整个符号的上下文一起返回。所以用法是：跨模块追链路、找实现位置、看改动的波及面 → 用图；已经锁定要读哪个小文件 → 直接读。

## 已知限制

- 只按符号名做词法匹配，**中文提问基本搜不到**（"设置页如何保存规则资产" 返回无结果）。要用符号名或英文关键词提问。
- 单次返回约 1.2–1.6 万字，即使是不相关的问题也给这么多。连着问多个问题时，这些内容会留在上下文里，后续对话反而更贵。
- 首次全量索引会卡住（本轮见到被中断、遗留 89 万条未解析引用）；重建一次即正常。改过 `codegraph.json` 后必须 `codegraph index --force`。
- 后台守护进程会常驻（`codegraph daemon` 可查/停），文件改动约 1 秒内自动同步，实测增删符号都能追上。
