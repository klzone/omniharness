# DataMasker 后续路线图（OD-ARCH-139 · 只登记不实施）

> 阶段边界：每个 Task 独立立项、独立验收；后续可按 Task 1 实际架构微调，但不得合并阶段。

## Task 2（OD-ARCH-141 候选）：Markdown / YAML / Obsidian 结构适配
- 区域策略表：代码块/行内代码默认跳过（可配置）、Frontmatter 默认处理、WikiLink 默认只处理显示文本、链接目标不动（目标脱敏会断链——如需处理目标须建立双链重建机制，单独立项）。
- 逐区域扫描替换，永久禁止"解析再序列化"。
- 验收：结构保真测试（改前后除占位符外逐字节一致，含注释、空行、表格对齐）。

## Task 3（OD-ARCH-142 候选）：安全加固与异常审计
- 审计日志只记计数与类型（时间、类型、数量、ok/ok 原因），不记原文与映射。
- 词典文件完整性（hash 记录与变更提醒）；并发使用约束文档化（SessionScope 线程安全性为 Task 3 决策点）。
- persist 泄漏面收口：MaskMapping 序列化能力按最小化原则再评估。

## Task 4（OD-ARCH-143 候选）：接入 LLM 调用链（强制点）
- 引擎 submit_task 出站前 mask（按 intent/session 建映射）；会话事件回程 unmask；ok=False 拦截并给用户明确提示。
- 本阶段验收含一条硬性检查："绕过脱敏直连云端模型的路径是否存在"——存在即不通过。
- 与模型路由/凭证的边界：只做出入站文本处理，不碰路由与密钥。

## Task 5（OD-ARCH-144 候选）：知识库批量处理与端到端验证
- 对 Obsidian 库副本（不碰原件）批量脱敏→还原往返演练；抽样人工核验结构与内容保真。
- 与 llm-wiki / 检索链路的联调验收。

## 依赖关系
Task 1 → Task 2（结构适配在核心引擎之上）→ Task 4（集成需要稳定的 mask/unmask 语义）；Task 3 可与 Task 2 并行；Task 5 依赖 Task 2 + Task 4。
