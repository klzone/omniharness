# OmniDesk 知识库总体规划基线

> 状态：总体规划基线已于 2026-10-26 获用户批准；阶段实施仍须按 PLANS.md 逐阶段形成详细计划并经用户批准。  
> 日期：2026-10-26  
> 范围：基于用户提供的知识库需求基线和当前仓库审查提出的架构与阶段建议。当前产品代码尚未因本规划而改动。

## 1. 目标与边界

OmniDesk 知识库应成为以用户本地 Markdown 文件为事实来源的独立工作入口。正文和普通附件留在用户指定目录；OmniDesk 负责安全浏览、编辑、搜索、链接解析和可视化。索引是可重建的派生数据。Obsidian 可继续作为另一个编辑器使用，但不是运行依赖，OmniDesk 不改写其配置或插件。

基础功能须在离线、无 Obsidian、无 LLM 时可用。AI 整理是后续可审查的增强能力，不能成为浏览、搜索、编辑、双链或图谱的前置条件。首期按单用户、单一本地知识库推进；多库联邦、实时协作、跨设备同步、向量数据库和通用工作流不进入首期。

本规划服从当前产品用途和数据边界：现有准入政策对真实工作材料、内部文件、设备、工具和模型端点设有独立授权要求；当前用户转述的有限许可不能扩展到知识库整理、其他用途、端点或设备。案件、线索、未公开调查信息、人物画像等禁入资料仍不得进入。提示词、脱敏和启发式扫描都不构成授权或代码级隔离。AI 阶段在具体用途和端点授权得到确认前，只能用合成或许可范围内的公开资料验证。

## 3. 目标模块与架构边界

1. **知识库根和文件服务（Rust/Tauri）：** 校验用户选定的根，执行目录扫描、读取、附件打开及后续写入边界。路径规范化、根内检查、符号链接拒绝、文件大小/类型限制、原子写和外部变更检测由宿主强制执行。
2. **解析与索引：** Markdown 原文为保存基础；解析出的 Frontmatter、标签、别名、链接和图关系均可重建。全量重建和增量刷新共用一套解析事实。
3. **知识 UI（React）：** 目录/列表、查看/编辑、属性和关键词搜索、关系导航、图谱及健康问题展示。UI 不直接读写文件系统，不决定授权。
4. **后续 AI 整理：** 复用 OmniDesk 现有 Runtime、Skill 和任务边界，执行 Ingest/Query/Lint/Refine；原始来源只读，知识页面差异逐项审查后才写入。不新建 Runtime、通用任务引擎或注册中心。
5. **数据位置：** 知识资产始终由用户指定目录保存；配置沿用应用数据根。派生缓存放在仓库外且可删后重建，默认不持久化正文片段。任何真实用户资料不进入 Git、夹具、通用日志或未经授权的模型/工具/环境。

### 根目录、扫描与文件变更候选策略

- 建议新增独立 knowledge_vault_root 配置，首期一个根；保留现有 library_root 对工作记录、成果和 @ 引用的既有语义。P1 核清全部消费者后确认，禁止自动迁移或把旧根指向新 Vault。
- 根须为准入的绝对路径；规范化后拒绝越界、路径穿越和符号链接。默认跳过隐藏目录及明确排除项，报告扫描、跳过和错误数量。常见缓存/依赖目录的排除名单在 P1 用合成 Vault 固定；不读取或修改 Obsidian 配置。
- 首期笔记只接受 UTF-8 Markdown；附件可列出并安全打开，不在首期解析或编辑二进制。PDF/DOCX 提取放到 AI 导入阶段评估。
- 初次全量扫描；打开、手动刷新和 OmniDesk 写入后执行对账。按相对路径、大小、mtime 与内容哈希识别变化，只重解析变更文件。首期不承诺后台实时监听；性能不达标后才比较 watcher 与轮询。
- 外部编辑在刷新时发现；保存前重算原文件哈希，发生外部修改就中止写入并要求比较/重载，禁止静默覆盖。重命名/移动先列出受影响链接，未获确认不自动批量改写。
- 先使用内存索引。只有合成规模测试证明冷启动或查询无法达标，才评估应用数据根下的可重建缓存；数据库不是事实来源，默认不保存全文或向量。

## 4. Markdown 与链接解析基线

- Frontmatter 只解析文件开头 YAML 供属性、标签和别名展示；原文围栏和正文保持不变。未知结构原样保留；解析错误显示警告，不隐藏笔记或阻止正文编辑。
- 标签识别 Frontmatter tags 与正文 #tag，忽略代码围栏中的伪标签。筛选规范化规则需在固定夹具中定义，原文大小写和层级不被改写。
- 首批识别 [[note]]、[[note|alias]]、[[note#heading]]、[[note^block]]；解析目标与显示文本分开。标题/块定位不唯一时明确显示歧义或未解析。
- 识别相对 Markdown 文件/标题链接、图片与附件链接；识别 ![[file]] 嵌入。越界或缺失目标明确标记，不访问根外路径。无法预览的附件仍保留原始链接并提供安全打开动作。
- 解析顺序：精确相对路径，再唯一标题/别名；重名目标显示候选，不静默选择。暂不支持的 Obsidian 扩展保留原文并标明未支持。
- 图谱边仅来自笔记内解析成功的链接；目录、标签和类型只是筛选属性，不伪造双链事实。

## 5. 分阶段计划与验收门槛

各阶段必须独立形成详细计划并获批准后实施。每阶段完成后记录实际 diff、隔离测试和未验证事项到 STATUS.md，并由 ARCHITECT 在 REVIEW.md 独立验收。未通过则只修复失败步骤，不进入下一阶段。

### P0：现状与准入审计

- 输入：用户需求、当前代码/共享状态、知识检索与入库政策、现有测试契约。
- 输出：本文件所列复用清单、缺口、边界和阶段验收基线。
- 验收：现存能力与规划能力已区分；候选方案未写成定案；未读取真实知识资产；总体方案获用户确认。
- 本次证据：文件事实及定向静态审查；无运行测试或模型调用。

### P1：单库根目录和只读访问边界

- 动作：为用户选定的 Vault/Markdown 目录建立独立配置、Rust 宿主只读枚举/读取/刷新/扫描状态接口和合成夹具。
- 输入：library_root、引用根、AppPaths 与安全校验现状及获批规划。
- 输出：可验证的只读访问契约、默认排除和错误报告；不含编辑和持久索引。
- 验收：合成 Obsidian 风格目录和普通 Markdown 目录均可读取；统计文件/跳过/错误；拒绝根外路径、路径穿越、符号链接越界、非普通文件和超限文件；旧设置兼容、不迁移文件；仓库/runtime/用户数据根无变化。
- 阶段门：Rust 单测、宿主集成测试及隔离窗口设置/扫描验证通过，并记录合成规模的冷扫描基线。

### P2：笔记浏览、属性、关键词搜索与安全编辑

- 动作：实现浏览、详情、Frontmatter/标签筛选、关键词搜索、Markdown 查看/编辑和新建。
- 输入：P1 通过的根访问接口与固定 Frontmatter 夹具。
- 输出：离线可用的文件型知识管理能力。
- 验收：属性和正文定位正确，搜索可解释；未知或无效 Frontmatter 原文不丢；写回文件仍是可读 Markdown；外部变更时拒绝覆盖；取消、写失败和应用重启不损坏原文；附件仅安全打开。
- 暂缓：批量编辑、永久删除、复杂归档、自动重写链接、附件文本提取。

### P3：双链和反向链接

- 动作：增加可重建链接解析索引及关系导航。
- 输入：P2 文件列表/元数据接口和语法矩阵。
- 输出：正向/反向链接、未解析/歧义链接、孤立笔记和目标跳转。
- 验收：固定 Vault 解析结果逐项匹配黄金预期；重名不误解析；不支持语法保留且显式标记；增删改和全量重建结果一致；失效标题/块定位有清楚回退。

### P4：知识图谱与链接健康视图

- 动作：基于 P3 唯一链接事实呈现局部/全局图谱、筛选、聚焦和导航。
- 输入：P3 索引接口与知识 UI。
- 输出：关系视图和轻量链接健康列表。
- 验收：图边与链接索引一致；节点可打开笔记；目录/标签/类型筛选有效；孤立、未解析、高连接度状态可见；在 P1/P2 测得并预先写明的合成规模下不阻塞界面。
- 依赖：先用现有前端能力；达到实测瓶颈后才引入专用图可视化依赖。

### P5：来源收件箱及 AI Ingest/Query 建议

- 动作：在明确获准的合成/公开资料范围内生成带来源的主题建议和逐文件差异预览。
- 输入：P1–P3、既有 Runtime/Skill、用途/材料/端点授权。
- 输出：来源登记、主题建议和可拒绝的预览；原始来源只读。
- 验收：建议能定位到来源文件和片段；区分原文事实、摘要、推断和待核实；冲突并列；模型失败/取消/拒绝不改源文件和知识页面；模型/输入规模/成本估算可用性明确，无实际 usage 时显示未知；离线基础能力回归通过。
- 门槛：不得由本规划或既有有限许可推定真实内部材料、云端端点或其他设备获准。

### P6：Lint 与审查式 Refine

- 动作：生成可定位的链接、来源、重复、过期和冲突问题；为修复提供逐项预览与确认。
- 输入：P3/P5 和文件差异协议。
- 输出：可定位、可拒绝、可取消、可重试的建议。
- 验收：问题定位到文件和标题/行；拒绝项不写入；确认项写入前重验外部变更并记录时间/理由/来源；失败状态清楚；撤销/恢复经合成文件测试证明。

### P7：受控 Workstation/Skill 集成

- 动作：为明确选择的工作站/Skill 提供最小只读知识引用和草稿输出能力。
- 输入：P1–P6 契约与最小访问配置。
- 输出：可见的工作站知识库绑定和来源引用。
- 验收：宿主强制获准根/文件范围；跨工作站测试证明拒绝越权；默认不写公共知识库，任务成果先成待整理草稿；撤销绑定后新任务无法读取。
- 边界：不改 DSH Runtime，不建新 Runtime/通用权限平台。

### P8：扩展、同步、恢复和发布验收

- 动作：单库稳定且有实际需要后，评估多库、跨设备冲突、恢复和规模优化。
- 输入：单库运行证据、实测冲突/性能数据和明确同步选择。
- 输出：可验证方案、使用说明、架构说明、测试报告、已知限制及回滚步骤。
- 验收：并发修改不静默覆盖、索引可独立重建、同步失败可恢复、真实大库性能有基准；发布材料不含真实知识内容或凭证。
- 暂缓：实时协作、向量数据库、复杂多用户权限和后台同步服务。

### 依赖顺序

P0 → P1 → P2 → P3 → P4；P2 和 P3 通过后可进入 P5；P5 → P6；P4 与 P6 通过后进入 P7；P4/P6 稳定且有证据支持后进入 P8。

## 6. 首期 MVP、成本与回滚

**建议首期 MVP：P1–P4。** 单个本地 Markdown/Vault 根、浏览与读取、Frontmatter/标签/别名展示、关键词搜索、笔记创建/编辑（外部变更保护）、双链/反链、局部/全局图谱。附件可列出和安全打开。无 Obsidian、LLM 或向量服务时仍可用。

首期暂缓：AI 整理、语义检索、PDF/DOCX 自动提取、批量编辑/删除、自动重写链接、多库联邦、同步、实时协作、访问统计和主题聚类。

成本：P1–P4 不调用模型；以合成库测量扫描、刷新、搜索和渲染后再定规模目标。AI 阶段限制单次文件/字节/主题数量，处理前呈现范围和费用估算；用量不可得时显示未知。先不引入数据库、向量服务或后台任务基础设施。

风险控制：旧 library_root 不改义；所有路径在宿主重验；外部修改中止保存；未知 Markdown 语法只保留不重写；图谱性能以合成基准验证；AI 源只读、逐项差异、冲突并列、人工确认。

回滚：P1 可回退新配置/读取代码，不移动用户文件；索引可停用并从源文件重建；单文件保存失败保持原文，冲突时不写；AI 拒绝/取消不写入，已确认修改须有差异和阶段验证过的恢复办法。任何阶段不通过均停留当前阶段，不清理既有工作区改动或用户数据。
