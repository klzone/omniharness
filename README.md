# OmniDesk Discipline

一个面向个人的本地 AI 工作台：把工作记录、复盘、任务、写作与资料整理成可追溯、可复核、可归档的工作流。数据保存在你自己的电脑上，模型只是可替换的执行引擎。

## 它是什么

OmniDesk 不是通用聊天工具，也不是 DSH 的换皮界面。它围绕“一个人长期做专业工作”组织：

- 工作记录不是聊天记录，而是有日期、分类、来源和状态的可回溯条目；
- 任务不是待办清单，而是带重要性、紧急度、排期和来源依据的工作对象；
- 写作不是一次生成，而是需求解析、素材收集、大纲确认、分章节写作、事实核验、审阅修订、定稿归档的完整流程；
- 知识不是临时问答，而是 Raw、Wiki、Governance、Index 四层可重建资料库；
- 所有落盘、定稿、归档和状态迁移都由你确认，AI 只产生候选与建议。

## 主要功能

### 记录与复盘

- 随手记与周视图：快速记下当天工作，后续整理成正式记录。
- 周报、月报、季报、年报：按周期汇总工作记录，生成结构化复盘。
- 记录与任务双向关联：从记录提取任务候选，经你确认后落库，来源可追溯。

### 任务与项目

- 四象限视图：按重要性和紧急度组织任务，支持人工覆盖象限与重要性判断。
- 智能排期与甘特图：结合工作时间与容量生成排期建议；已锁定和已确认的安排不被覆盖，冲突显式提示。
- 项目跟进：事项、负责人代号、进度、逾期提示；项目关联任务、记录和素材。

### 写作与素材

- 素材篮：十类素材分类、审核状态、原文引用与来源定位，和任务、项目、知识双向关联。
- AI 文稿工作台：需求解析、素材收集、大纲确认、分章节写作、事实核验、审阅修订、定稿；事实核验区分直接来源、冲突、无来源和分析判断。
- 版本快照与回滚：每次修改可回看，口径冲突只提示、不擅自合并。

### 知识库

- Raw 原始资料、Wiki 结构化知识、Governance 治理记录、Index 可重建索引四层。
- 导入、人工审核、冲突处理、质量与过期检测、双链与知识图谱。
- 定稿成果可显式归档进知识库；工作记录和任务留在本地工作区，不混入知识检索。

### 会话与模型

- 首页以对话为工作入口，执行过程按时间线展示思考与工具调用，可展开回看。
- 会话可分支、可继续、可回看历史；历史会话独立入口。
- 模型端点由你自己配置：本地、内网、公网分区授权，缺省关闭；支持 OpenAI 兼容端点、思考模式开关和模型切换。
- 模型调用前有红线扫描与脱敏闸门；工具入参与结果不写入通用日志。

### 导出与归档

- Markdown、Word（公文样式）、PDF（阅读版式）、公众号 HTML 四种导出形态。
- 周报与项目成果归档；定稿 Markdown 可回流知识治理流程。

## 适合谁

- **个人知识工作者**：需要长期积累工作记录、复盘、材料和项目跟进的人，例如综合文稿、研究、咨询、行政与项目岗位。
- **需要可追溯工作证据的人**：希望每个结论、每份材料都能回到原始记录、素材或知识原文，而不是一次性聊天输出。
- **重视数据自主的人**：希望会话、成果、配置都在本机目录，能迁移、能备份，不依赖某个云平台。
- **需要模型可控的人**：希望自己选择端点、控制权限、替换执行引擎，而不是被单一模型或服务商锁定。
- **独立开发者与小团队中的个人**：想用自己的工作流验证 AI 工作台，而不是直接上企业级平台。

不适合的使用场景：多人实时协作与企业级权限审计、案件办理、线索研判、人物画像、针对具体个人的评价记录或自动纪律判断。这些不属于当前产品边界。

## 为什么做这个（开发目的）

OmniDesk 的开发目的不是再做一个聊天壳，而是验证一种更可靠的个人 AI 工作方式：

1. **独立产品**：OmniDesk 有自己的任务入口、工作流、规则、数据和成果体验；DSH 只是当前锁定的执行引擎，不是产品边界。
2. **本地优先**：数据放在本机可读、可备份的目录；文件与 Git 是当前状态、知识和评测资产的首选载体。
3. **确认制**：AI 产生候选、建议和草稿，落盘、定稿、归档和状态迁移由人触发；未经确认的内容不进入可信集合。
4. **事实优先**：文稿结论要能追溯到素材或知识原文；无来源不编造，冲突不合并。
5. **可验证**：每次改动都通过源码、构建、测试和验收记录来证明；关键结论保留可回溯的验收记录。
6. **可替换引擎**：不修改 DSH Runtime，不把其私有数据格式、UI 或内部实现当成产品边界；引擎变化不应绑死产品。

## 安装与运行

最新发布见 [Releases](https://github.com/klzone/omniharness/releases)：macOS 通用版 .dmg 与 Windows x64 安装包。

安装包内置 DSH 运行时和 Python 依赖模块；需要系统已安装 Node.js 24.9+ 与 Python 3.10+，首次启动会做依赖自检并明确提示缺项。

从源码运行：

    git clone https://github.com/klzone/omniharness.git
    cd omniharness && scripts/setup.sh
    scripts/omnidesk-dev.sh

需要自行配置模型端点（OpenAI 兼容接口）；未配置时应用可启动，模型相关功能不可用。

## 架构

| 层 | 技术 | 职责 |
| --- | --- | --- |
| 桌面壳 | Tauri 2 + React + TypeScript | 窗口、场景页、对话与工作台 UI |
| 宿主 | Rust | 任务生命周期、写确认终检、权限判定、进程管理 |
| 适配层 | Python | DSH Web-API/ACP 通道、事件归一化、会话恢复 |
| 执行引擎 | DSH（锁定版本，不改核心） | 模型调用、工具执行、会话 |

数据根在本地 OmniDesk 目录（会话线程、成果、配置、日志）；仓库不保存用户数据。

## 数据与安全

- 真实业务材料、凭证、会话日志不进入 Git；提交前有红线扫描。
- 模型权限按本地、内网、公网分区授权，缺省关闭，由你在设置中逐项开启。
- 敏感内容在写入与模型调用前经过扫描与脱敏；工具入参与结果不进入通用日志。
- 不读取、打印、复制或提交凭证；不擅自更改模型路由。

## 项目边界

- 不修改 runtime/ 下的 DSH Runtime；升级 DSH 先在副本跑回归。
- 不建设通用 Agent 平台、插件市场或微服务；按真实使用证据逐步扩展。
- 不把 AI 输出当作确定性计算；模型只协助解释与起草，人负责核对与定稿。
