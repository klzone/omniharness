# OD-WR-509 工作记录分页双页签改造

日期：2026-11-12

## 触发与范围

用户提供工作记录分页设计图，并要求按《OmniDesk 工作记录模块 1.0 总体规划与设计任务书》改造为「工作记录 / 周期复盘」两个页签。本轮只改前端信息架构、视觉与交互接线，不改 Rust 数据契约、模型路由或凭证。

改动文件：

- desktop/src/shell/WorkRecordPage.tsx：页头、两页签、审核浮层。
- desktop/src/shell/WorkRecordLibrary.tsx：时间线、筛选、右栏概览、复盘入口、快捷操作、详情抽屉、任务关联入口。
- desktop/src/shell/ReviewArchive.tsx：周期复盘档案、生成入口、详情。
- desktop/src/shell/RecordTaskLinkDialog.tsx：记录关联已有任务。
- desktop/src/shell/TaskReviewPanel.tsx：增加浮层内嵌布局。
- desktop/src/theme.css：新增 .wr-* 材质、页头、时间线卡面、抽屉与弹窗样式。
- 验证脚本：verify_wr_509.py；同步更新 301/504/506/507 的页签与样式断言。

## 参考布局（screenshots-design-inspiration MCP）

看了 Notion 的 Journal 条目列表与 Linear 的 issue 列表：Notion 用「日期在右、分类小标签在左」让记录列表可以快速扫读；Linear 用紧凑行高与右侧时间戳承载较密的元数据。本页借鉴的是「时间线行内分类 + 右侧状态/时间」的扫读顺序，以及把搜索、时间范围、附加筛选收在同一行，而不是新增侧边聊天入口。

## 实装的功能

1. 页头「工作记录」+ 副标题 + 「本月记录 N 条」；两个页签：工作记录、周期复盘。
2. 时间线按日期倒序，组内按当天时间正序；日期组头显示日期、星期、年份（跨年时）、条数与当日摘要入口。
3. 记录卡显示时间、分类、标题、摘要、来源、关联任务、解析状态与草稿标记；点击打开右侧详情抽屉。
4. 详情保留正文 Markdown、原始输入（只读）、修订历史、关联知识、关联复盘/文稿、编辑/删除/解析/重新整理/交给 AI。
5. 右栏本月概览：记录总数、已解析、待解析；三个数字均可作为真实筛选入口。
6. 一键生成本月复盘；快捷操作：生成周复盘、生成月总结、整理选中记录、关联任务。
7. 关联任务打开任务选择弹窗，只写 linked_task_ids，不改任务状态。
8. 审核候选改为浮层，仍挂载既有 TaskReviewPanel；解析产生候选后自动打开，关闭后列表重新读盘。
9. 周期复盘页保留档案列表、周期/状态/日期筛选、详情、导出、草稿重新生成、已确认禁止覆盖、记录与任务引用；新增周/月/季/年生成入口。
10. 搜索、月份/日期范围、分类 chips、解析状态、只看草稿与手动记录均保留。

## 页面收敛

- 原「审核」页签改为浮层；「任务」页签移除，任务管理仍在项目跟踪分页；「周视图」页签移除，周期复盘覆盖周/月/季/年档案。
- 首页仍是唯一对话入口；页面所有「生成/整理/交给 AI」动作只预填首页对话，不自动发送。

## 已知限制与如实说明

1. 记录状态沿用既有 ai_analysis_status：已解析 / 未解析 / 解析失败。没有新增独立的「确认」字段，因此界面不把解析状态写成「已确认」；概览标签为「已解析 / 待解析」。
2. 真实模型生成摘要与复盘的质量未在本轮重测；503/505 的既有契约验证保持通过，真实生成仍需用户实测。
3. 快捷操作只预填首页对话，不自动发送；这是既有 requestNewThread 的语义。
4. 时间线组内排序由倒序改为当天时间正序，同步更新 504 的排序断言；日期组仍为倒序。
5. 任务管理不再内嵌本页，仍可从 Dock 的「项目跟踪」进入；审核候选浮层保留了原审核台的全部动作。
