### 1.1 文案核实（源码事实 + 渲染截图）

本机回环 / 非回环（私有·链路本地、公网）分类说明 ✅ · 默认全部关闭 ✅ · 无法确认位置的端点永不放行 ✅ ·

### 1.2 假端点验证（配置写入与生效路径）

| 步骤 | 观察 |
| --- | --- |
| 默认状态 | 三个权限开关全部**未勾选**；设置文件 `model_permissions.local=false` |
| 权限关闭时提交 | 首页对话输入框的占位提示变为「**模型权限未开启：可在设置中确认端点后启用**」，发送按钮不可用；**未产生任何任务**（20 s 内任务台账无记录）——即**不出错、不静默降级**：真实原因摆在界面上 |
| 界面开启「本机模型」 | 设置文件写入 `model_permissions.local=true`；首页占位提示随后变回「与 OmniDesk 协同探索…」（准入状态已传播） |
| 开启后真实调用 | 场景页「读取材料 → 生成模型初稿」走真实模型链路，终态 `succeeded`，返回合成端点内容「合成回复内容」 |

结论：**端点判定 → 权限开关 → 配置落盘 → 提交放行 → 模型返回**这条链路在真实窗口里打通。

## 2. 使用记录持久化（阶段 B，`od030-run7.json`）

- **落盘位置（正式根，仓库外）：** `~/OmniDesk/app/logs/usage.jsonl`。
  该路径来自应用数据根解析（`OMNIDESK_APP_DATA_ROOT` 未覆盖时为 `$HOME/OmniDesk/app`），
  **产品代码无需改动**——此前自检落在 `/tmp` 只是因为测试覆盖了该环境变量。
- **格式：** 一行一条 JSON，只含枚举与时间
  （`record_id / schema / task_type / recorded_at / completed / usable / rework_kind / blocker /
  duration_bucket / reuse_willingness`）；**无输入、输出、正文、标题、路径或会话**。
- **读回：** 界面显示「查看记录（2）」，展开后逐条列出。
- **清理：** 用**产品自带的逐条删除**清掉本轮写入的 2 条合成记录 → 文件回到 **0 字节**，
  正式根保持干净，用户的首次真实使用不会混入测试数据。
- **边界核对（目录快照前后比对）：** `~/OmniDesk/quarantine/`（真实案件材料）与 `~/OmniDesk/runtime/`
  （含凭证）**均未新增、未改动、未删除**；`~/OmniDesk/app/config/offline-flows.v1.json`
  是应用首次运行写入的**可编辑流程包副本**（2918 字节，无凭证、无用户数据），属正常首启行为。
- **保留期限与清理规则：** 已登记在 [docs/OmniDesk-Desktop-Data-Layout.md §5.1](../../../docs/OmniDesk-Desktop-Data-Layout.md)：
  默认不做自动清理；由用户在界面逐条或整体清除；验证数据必须在验证后删除；不进 Git；不得与
  `quarantine/`、`runtime/` 混放混备。
