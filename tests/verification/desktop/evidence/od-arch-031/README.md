### A.2 实测（真实窗口，用户会话，正式环境）

- 设置页按钮（AT-SPI 实读）：`['撤销全部模型权限', '刷新端点信息', '打开 DSH 设置（登记 key）', '刷新状态', '打开当前目录', '校验并保存', …]` — **两个入口在端点已识别时可见可点**。
- 点「打开 DSH 设置」→ **引擎同款的 DSH 被拉起**（`node <runtime>/dsh/lib/bin.js web` 进程出现，本地地址与浏览器自动打开），
  界面给出 DSH 数据根、凭据文件与启动日志路径；宿主全程未读、未写、未打印任何凭证值。
- **实测该 DSH 的环境**：`DSH_HOME=/home/kevin/OmniDesk/runtime/dsh-home`、`DSH_AGENTS_HOME=…/agents-home`——
  与引擎读的是**同一份**数据根（`evidence/od-arch-033/dsh-jump-check.py` 可复跑）。
- **首版曾有错**（已修）：原先拉起的是系统里那个 DSH Desktop，它读的是用户**自己那份** DSH 数据根，
  于是「在 DSH 界面里登记的模型配置」根本进不了 OmniDesk——用户实测发现并指出，现已改为同一份数据根。
- 端点**不可识别**状态：另起一个实例（空 DSH 数据根）复核 → 两个入口同样可见；权限开关在端点可识别时正常渲染（3 个）。
  **限制：** 本机 DSH 在没有自定义 baseURL 时会回落到 DeepSeek 默认端点，因此**自然构造不出「端点不可识别」的状态**；
  该分支是按代码条件渲染的（`!facts || factsError`），已由源码核对，**未做真实不可识别状态的截图**。
- 回归：Rust **144/144**（新增 1 条 `dsh_desktop_lookup_finds_only_existing_desktop_files`）、`npx tsc --noEmit` 0、
  `npm run build` 通过。

### A.3 需要 ARCHITECT 注意的**计划偏离**

计划原文写「宿主不新增命令」，但 Part A 第 1 条要求设置页能**拉起 DSH Desktop 的设置界面**——
Tauri v2 前端没有可用的外部启动器（`@tauri-apps/plugin-opener` 未安装），不做宿主命令就无法实现。
因此新增了**一个**最小命令 `task_open_dsh_settings`：无参数、固定白名单、不读写凭证、失败即明确报错。
这是**唯一**的新增宿主能力（不涉及协议、不涉及通信层），已在 REVIEW.md 标注，供复核确认。

## Part B：项目与会话**模块**（首页不做分栏、不出目录树）

> **更正（2026-10-20，用户当场纠正）：** 早先一版把「项目 / 会话」树直接放到了**首页左侧**、并把首页做成左右分栏——
> 这是误读。用户的意图是：左侧 Dock 是进各场景（周报 / 撰写材料 / 项目跟进…）的入口，

> 现已按此改回：首页 = 用户已确认的对话中枢版式（无目录树、无分栏）；项目与会话在独立的「项目与会话」模块页里。

### B.1 现在的结构

- **首页**：完全回到用户 2026-10-19 确认的版式（问候 + 机器人 + 今日重点推进 + 日程节律 + 全宽对话 +
  权限/Token 行），**没有**项目树、**没有**左右分栏。截图 `shots/od031-home-no-rail.png`。
- **「项目与会话」模块页**（Dock 入口，原「会话与任务」；标签改为「项目与会话」）：

    与 **本机对话**（本工作台自己的对话草稿；第一轮提交后由引擎产生 DSH 会话，随即归入「引擎项目」）；

### B.4 没能自动化的部分（诚实记录）

- **真实窗口里用合成键盘输入驱动对话，本轮做不到**：XTEST 注入的字符**进不了**输入框
  （输入框能被点中并获得焦点，但字符不落）。已排除的原因：DSH Desktop 等其它应用抢占合成器焦点
  （关闭后仍复现）。因此「在 GUI 里打字 → 端点收到带上下文的请求」这一段**没有**端到端自动化证据；
  改由**脚本级**验证提示词组装（上面 12 例）+ 既有 028 验收（提交链路本身）覆盖。
  证据：`partb-run1.json`（记录了「点了发送但没有任务」的现场）。
- **「同一引擎会话里的多轮」在当前协议下不存在**：宿主↔引擎的动词里只有
  `submit_task`（每次 `session/new`）、`list_sessions`、`recover_session`（`session/resume`，不重放），
  **没有**「向既有会话再发一条」的动词。因此工作台的连续对话是**每轮一个新 DSH 会话 + 工作台把上文重放进下一轮提示**，
  这一点已写进 `Workspace.tsx` 的文件头注释与本索引，不含糊。
- **「AI 自主调 Skill」未验证**：DSH profile 是否在 headless/acp 模式下加载 Skill，本轮未测。
- **本机对话的上下文**存在**本地存储**（只在本机、只在这份前端里），不进 Git、不进成果目录；
  换 dev/release 两个来源（不同 origin）时互不可见。
