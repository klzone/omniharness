# OD-ARCH-040 证据索引：对话为主的两层布局（卡片在下 · 对话在上 · 指针进对话区卡片渐隐）

> 执行日：2026-10-20。起因：用户澄清 UI 口径 —— 「对话历史占到上下全屏幕，平时顶部的卡片显示，
> 当鼠标放在对话框或对话历史上时，卡片就渐隐，对话历史显示在卡片上面」。

## 1. 口径（本轮最终口径，取代上一轮的误读）

上一轮（OD-ARCH-039）把「鼠标焦点在哪里，哪里显示在最前端，其他模块渐隐显示在他下面」理解为
**卡片之间**互相抢层级，做成了「卡片带之间的渐隐 + 前置」，**已按本轮口径撤回**。

正确口径是**页面两层**：

| 层 | 内容 | 行为 |
| --- | --- | --- |
| 下层（z-0） | 顶部卡片区（首页：问候 + 机器人/今日重点推进/日程节律；场景页：提醒栏 + 历史对话/成果进度） | **平时可见**；指针进入对话区时**渐隐**并让出点击 |
| 上层（z-10） | 对话（对话历史 + 输入框） | **占满上下全屏**；指针在其上时**上移占满顶部**，即「对话历史显示在卡片上面」 |

## 2. 实现要点

- `desktop/src/shell/SceneScaffold.tsx` 改为两层结构：
  - 卡片区改为 `absolute inset-x-0 top-0 z-0` 的**背景层**（内容多高就多高，`ResizeObserver` 实测高度）；
  - 对话区改为 `relative z-10 flex-1`，用 `padding-top` = 卡片带高度 / 0 做 300ms 位移。
- **判定用指针在容器内的纵向位置**，不用元素 hover：两层叠加时元素 hover 会互相遮挡，
  纯 hover 判定会出现「卡片被对话区盖住后永远回不来」的死角。
- 指针离开窗口 → 恢复卡片显示。
- 时序处理：卡片内容异步就绪 ⇒ 卡片带高度会变；高度一变立刻**重判一次**指针位置
  （否则首帧高度为 0 时会把「指针在卡片上」误判成「已进入对话区」）。
