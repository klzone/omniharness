# 开发流程改进建议（待确认，不实施）

| 对应问题 | 建议 | 预期收益 | 风险与验证 |
|---|---|---|---|
| 长线程带入过多历史（有线索，无项目级量化） | 一个清晰阶段/计划完成后，用短交接摘要开启新线程；摘要只含当前目标、HEAD/工作区、允许范围、验收与遗留项 | 减少重复背景输入 | 交接遗漏会造成返工；试点时统计澄清/重读轮次 |
| 产品验收发现偏晚 | 计划开头用一页“用户可见完成定义”，至少列一个成功、失败和取消流程；开发前先确认窗口预期 | 减少实现后方向性返工 | 可能增加一次早期确认，但应减少后期重做；用返工轮数验证 |
| 计划实施被拆成过多小轮 | 一个获批计划内连续完成相邻实现任务；只有阻塞、需求变化或重大设计问题才停下重规划 | 降低重复上下文与状态交代 | 范围扩大风险；计划必须列文件边界和停止条件 |
| 测试输出重复贴入对话 | 成功时只留命令、通过数、证据路径；失败时只读失败用例和最小日志片段；集中阶段末验收 | 降低无关输出 | 可能隐藏失败上下文；失败时必须扩读足以定位根因的信息 |
| Token 数据无法归属任务 | 试点前后记录同一执行线程的请求级输入/输出/缓存/恢复量；无可靠线程映射则标未知，不估算 | 让后续效果可比较 | 遥测不完整或跨线程会破坏可比性；明确数据源与统计窗口 |
| 同根因反复修复 | 连续两轮仍未解决即停止，交 ARCHITECT 做根因判断 | 防止盲目循环 | 不得将停止规则用于跳过必要修复；记录失败证据 |

保留项：最终计划要求的完整回归、独立代码审查、安全与数据边界检查、高风险变更前置审查。节省 Token 不以删测试、降低覆盖或跳过验收实现。

本文件只是审计建议；不改写 AGENTS.md、计划模板、模型路由或其他协作规则。须用户确认后才能纳入试点计划。
