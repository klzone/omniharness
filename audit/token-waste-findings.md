# 重复工作与可避免消耗

| 发现 | 证据与频率 | 影响判断 | 置信度 |
|---|---|---|---|
| 长线程可能反复携带历史上下文 | 历史审计摘要记录一个约 5,394 请求的长线程；但原始记录和项目归属本轮无法核对 | 若每轮均带入长历史，会增加请求输入；无法从现有证据算出其中可避免的比例 | 中（现象来自历史摘要，归属未复核） |
| 计划、执行、审查之间重复交代状态 | 共享文件和历史会话显示同一工作由 ARCHITECT 规划、BUILDER 执行、ARCHITECT 再审；新阶段常需带入目标、边界、证据 | 部分重复是独立验收所需；可压缩交接，但不能取消独立复核 | 中 |
| 同一计划经历多轮补测/修正 | OD-ARCH-024 有多轮补测记录；OD-ARCH-025 产品验收未通过后，026 重新校正目标并实施 | 暴露出早期产品验收标准不足、缺陷集中后置的返工风险；补测本身不能一概判为浪费 | 高（有项目记录） |
| 大量共享历史文件可能促使重读 | STATUS.md、REVIEW.md 含较长历史；本次读取已按当前摘要和标题缩小范围 | 全量重读会增加上下文，但没有日志证明每次任务都重读，也不能量化 Token | 中（结构事实；使用频率未验证） |
| 测试截图和完整回归是否过量 | GUI 计划含多张截图及多项回归，部分是界面/隔离/生命周期风险所必需 | 没有证据证明其不必要；不得作为削减测试的依据 | 低/待验证 |
| 无效重试 | 没有可核验的逐次失败、重试与成功关联记录 | 未证实 | 未知 |

不能据此下结论：“所有复核都是浪费”“GUI 截图都不必要”或“只要少跑测试就能省 Token”。当前证据最支持的改进是减少长线程和重复交接，同时把返工尽量前移到一次清晰的验收定义。
