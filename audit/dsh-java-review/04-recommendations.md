# 借鉴优先级与验证方案（待用户批准，未实施）

## P0 — 无
本次审计未发现 OmniDesk 已确认的高风险缺陷。

## P1 — 高价值小改动（合计 <100 行 + 2 测试）
### P1-1 执行入口 fail-closed 终检
1. 问题：写确认制覆盖写操作，但执行入口缺少对"存在未决审批/分区不匹配"的统一兜底。
2. dsh-java 证据：任务链对 PENDING_APPROVAL 在执行入口抛异常（README §3.5）。
3. OmniDesk 证据：pending_writes.rs 有确认卡，但执行侧无终检断言。
4. 借鉴方式：设计思想（终检模式），不引代码。
5. 范围：desktop/src-tauri 任务执行入口加一次校验；不改契约。
6. 风险：极低；可能拦截现有合法路径——用全量回归覆盖。
7. 验收：host_integration 新增用例"存在未决写卡时任务拒绝执行"；cargo 全量通过。
8. 不实施代价：未来新增执行路径需逐个记忆防绕过，属隐性维护成本。

### P1-2 会话日志版本化与迁移测试
1. 问题：~/OmniDesk 线程持久化文件无 version 字段；未来格式演进可能读不回旧会话（动摇"会话不丢"核心承诺）。
2. dsh-java 证据：SessionFormatMigrationTest、MigrationCatalogTest、LegacyEventAdapterTest。
3. OmniDesk 证据：045 线程落数据根，无版本/迁移机制。
4. 借鉴方式：设计思想（格式版本+迁移函数）。
5. 范围：日志写入加 version 字段；读取端对旧格式走迁移函数；仅对未来文件生效，不迁移历史数据。
6. 风险：低；迁移 bug 可能损坏读取——迁移只增不改写原文件，失败时保留原样并报错。
7. 验收：新增"旧格式样例→加载成功"测试；强杀恢复回归通过。
8. 不实施代价：每次演进线程格式都在积累不可读风险，越晚补越贵。
