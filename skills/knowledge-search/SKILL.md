# 知识检索与卡片维护 (Knowledge Search)

知识库是给 AI 读的，不是给人看的。省 token 靠**读得少**，不靠找得全。

## 一、两跳检索（硬约束，不许跳步）

1. **第一跳：只读索引。** 读 `库/知识库/索引.md`。每张卡一行：`- [标题](概念/文件名.md) | 标签：a, b | 一句话摘要`。
2. **第二跳：按标签定位。** 用提问关键词比对索引的标签、标题、摘要，取最贴近的一条。
3. **只加载命中的 1–2 张卡。** 打开卡片正文作答。

读取预算只有这三步。以下动作把成本从几百 token 抬到整库，**一律禁止**：`ls` / `glob` / `find` / 递归遍历 `概念/`、`方法/`；一次读多张卡或整个目录；索引没有就去猜目录名。

**没有命中时**：如实回答「当前知识库未收录」，说明查过哪些标签，可问是否建卡。不得用模型记忆补成结论，也不得解释卡里没有的条文。

**要逐字引用**条文、文号、条号时，卡片只是摘要，必须回到 frontmatter 的 `sources` 指向的原文读一次；读不到就说「仅有卡片摘要，原文未核」。

## 二、索引格式（省 token 的唯一入口）

索引第一步唯一要读，因此只放**一行一卡**，不放正文、不放目录树：

```markdown
# 知识库索引

## 概念
- [专项检查的频次要求](概念/专项检查频次.md) | 标签：监督, 专项检查, 频次 | 一类单位每季度不少于一次。

## 方法
- [问题线索处置判断](方法/线索处置判断.md) | 标签：线索, 处置 | 先定性质，再定承办，最后定时限。
```

摘要一句话、40 字内，写「这张卡能回答什么」。标签用读者会问的词，2–5 个。

## 三、卡片格式（一卡一概念）

位置：`库/知识库/概念/`（是什么、怎么规定）、`库/知识库/方法/`（怎么做、怎么判断）。文件名即标题。

```markdown
---
tags: [监督, 专项检查, 频次]
sources: [库/知识库/原文/xxx.md]
date: 2026-10-25
---

一句话定义。

## 展开
自包含的要点，不看别的卡也能懂。

## 相关
- [[相关卡片标题]]
```

- **一卡一概念**：一张卡回答一个问题；两个问题就拆两张。
- **正文 ≤ 300 字**（不含 frontmatter）。超了就是塞了两个概念，拆开。
- **自包含**：不写「详见上文」，卡片会被单独加载。
- **双链**：`[[卡片标题]]` 指向索引里已有的标题。
- **来源**：外部依据写进 `sources`；自己的判断、经验、推断在正文标「待核实」。

## 四、写卡流程（顺序固定）

1. **先查索引防重复**：已有同概念卡就**改那张**，不新建；标题不同但讲同一件事也算重复。
2. 再读一次该卡正文，确认是补充而不是覆盖别人的观点。
3. **写卡或改卡后立即同步索引**：新增补一行，改卡更新该行标题/标签/摘要。
4. 核对：索引每个链接能打开，卡片目录没有索引遗漏的卡。

删卡同步删索引行。移入 `库/inbox/` 或 `库/工作记录/` 的不算知识卡，不进索引。

## 五、Obsidian CLI：可用则用，不可用照常

先探测本机 `obsidian` 命令（Obsidian 1.12+ 在设置里开启）。**探测失败不是错误**，走普通文件读写，功能不减少。

| 动作 | 有 CLI | 无 CLI（降级） |
| --- | --- | --- |
| 建卡 / 移动 | CLI 执行，链接自动更新 | 直接写/移动文件，手工核对双链 |
| 双链校验 | CLI 查反向链接 | 搜 `[[标题]]` 是否对得上 |
| 列 inbox | CLI 列出 | 读目录列表 |

索引同步与防重复判断**始终由你完成**，不依赖 CLI。无法确认双链有效性时，如实说「未做双链校验」。

## 六、数据边界

- 只读 `库/` 内文件；库根默认 `~/OmniDesk/库`，用户绑到别处时以实际库根为准，不猜路径。
- 案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进库；遇到即停止并说明。
- 身份证号、手机号按 Profile 规则资产的掩码策略处理。
- 未收录就写未收录，不把「应该如此」写成「制度规定」。

## 七、自检

只读了索引 + 至多两张卡？引用有来源？自判断标了「待核实」？建卡前查了索引、写完同步了索引？
