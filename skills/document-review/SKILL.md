# 材料质量审查

## 一、用途

审查用户已有的文稿，给出可定位、可修改的问题清单与建议；不替代用户定稿。

## 二、触发与排除

- 触发：审稿、找问题、查合规风险、查 AI 味与空话、要修改建议或润色对比。
- 排除：从零起草或重写整篇（用 `material-writing`）；只做错别字或格式转换；要求研判案件事实或定性。

## 三、材料与依据

本技能目录下 `references/writing-style/` 有风格与避坑规则（`scripts/sync-skills.sh` 从仓库物化，用户可在本地替换）。审查前实际读取所需文件；未读取的规则不得在报告里说成已核验。`references/` 不存在时，在报告里说明资产未物化并提示同步。
- 依据顺序：用户提供的文稿与说明 > 本技能风格规则 > 公开法规原文（需要时用 `anysearch` 或 `knowledge-search` 核对）。
- 只评论文稿本身，不替用户补事实；引用法条时写全称与条号，未核对就标「未核」。

## 四、审查维度

1. **结构**：标题与内容是否对得上；层级是否清楚；有无交叉重复或段落脱节。
2. **事实与数据**：核心成效有无具体数据、时间、对象；有无大段无依据的定性吹嘘；数字与来源能否对上。
3. **文风**：是否违反 `references/writing-style/avoid-list.md`；有无「赋能」「闭环新生态」「深刻的不仅是…更是…」这类套话；句子是否啰嗦。
4. **合规**：法规、政策、政治术语的全称与表述是否准确；有无未经官方定性的推断或高风险表述。

## 五、输出契约

```markdown
# 《××材料名称》综合质量评估报告

## 一、综合评级
- 整体质量：优（90-100）/ 良（75-89）/ 待完善（<75）
- 核心评价：一两句话说明长处与最大短板。

## 二、维度诊断与问题清单
### 1. 结构与逻辑
- [问题] …（引原文短句定位）
- [建议] …

### 2. 事实与数据支撑
- [问题] …
- [补强建议] …

### 3. 表述朴素度（避坑自检）
- [不良表述] “…”（标明是否套话/空话）
- [替换方案] “…”

### 4. 政治与法规严谨性
- [结论] …（引用是否准确；未核对的标明）

## 三、靶向润色对比
- 原文段落：…
- 优化改写：…
```

## 六、质量清单与失败处理

清单：每条问题能指到原文；建议可执行；未核实的引用标「未核」；不替用户下定性结论；不把推测写成事实。
文稿涉及案件材料、线索、未公开审查调查信息、涉案人员或举报内容时，停止审查并说明；文稿缺失或无法读取时，直接说明缺什么，不凭空评分。
