# 项目跟踪

## 一、用途

把用户提供或工作台交来的项目、事项与任务事实，整理成能直接看进展、看卡点、看下步的简报。

## 二、触发与排除

- 触发：梳理多项目进展；排查逾期与阻塞；汇总会议纪要或 TODO 里的项目事项；整理下步安排。
- 排除：替用户新建或改任务状态（由工作台动作执行）；没有材料时凭空写项目进展；单纯查资料。

## 三、材料与事实

- 只写材料里的事实、状态、日期与责任人代号；不补造进度、完成度或交付结果。
- 截止日期与逾期天数以材料和工作台统计为准，不自行推算，不擅自调宽工期。
- 负责人只用用户明确给出的代号或职位称谓，不关联未经许可的个人信息。
- 记录冲突就并列指出，不挑一个当对的；缺关键信息写进「待确认事项」。
- 案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进入简报；遇到即停止并说明。

## 四、分析口径

先事实、后判断。进展写「做到哪一步」，状态写材料里的状态；没有进展说明的，只能据状态、截止日与关联记录判断，证据不足写「依据不足」。阻塞要写具体卡点与所需协同，不写空泛的「推进中」。

## 五、输出模板

```markdown
### 【整体状态】
（在跑、正常推进、阻塞、逾期的数量，只据材料）

### 【事项明细】
- **[项目/事项]**（状态：… · 责任：…）
  - 核心进展：…
  - 完成度/交付：…（没有就写「材料未给出」）

### 【逾期与阻塞】
- **[事项]**：卡点、原因、所需协同；逾期项写滞后天数。

### 【下步安排】
1. …

### 【待确认事项】
- 责任人不明、截止时间缺失或信息冲突的条目逐项列明。
```

## 六、质量清单与失败处理

清单：没有替用户宣布「已完成」；逾期与状态对得上材料；代号未混入敏感身份；不确定项都在「待确认事项」。
材料为空或只有项目名时，如实说明无法汇总，不生成假进展；需要查知识卡读 `knowledge-search`，需要联网核对读 `anysearch`，需要审校读 `document-review`。
