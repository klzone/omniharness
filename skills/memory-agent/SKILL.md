# 随手记：判断口径

只定口径，输出结构以工作台契约为准（示例省略空字段）。写盘由工作台执行，成功回执由它生成，reply_hint 留空，不说“已记录”。

## 一、意图
- note：说了某天做过的具体工作；补充或回答追问；日期指令（“都是周一的”）。
- instruction：要助手做事（查、搜、整理、起草）。不落盘，reply_hint 直接答，可引用索引。
- chat：寒暄，或“嗯、好、不用、是、否”纯确认。不落盘。
- uncertain：拿不准是事实还是对助手说的话。
- 带实质内容的回答（“在三楼会议室”）是补充，不是确认。事实与指令并存：记事实，指令留给下一句。

## 二、动作
- append：新事实。date 默认今天，用户说了日期按那天，限最近 14 天内、不晚于今天。一句多事拆多条，每条一段连续原话。
- merge：补充或回答追问，date+index 指向索引那条，text 只放补充。已含此内容不并。
- move：日期指令。索引里每个命中条目各出一条，to 不同于原日期；找不到就不动，reply_hint 说缺什么，不新建冒充。
- 指代（“那个材料”）按索引最近相关一条；对不上选 uncertain。
- text 取本轮用户原话的连续片段，不改写、不合并、不补字，标点空格不同无妨；单条不超 500 字，长篇取最关键一段。任一条不合规，整份作废。
- 同一条不既 merge 又 move；同一段不既 append 又 merge/move。

## 三、review
记录已保存，review 是事后跟进，不拦截。`missing` 是字符串数组；`task` 是 `{"suggest":布尔,"title":"待办标题"}`。
- missing/question：缺项会影响周报引用才问，限一句，只问最要紧的一项（时间、地点、人物、事件、影响或感受）。move、确认、补充后留空。
- errors：原话里明显的矛盾或日期冲突；没有就留空数组。
- task：仅当原话含明确后续待办才写 `{"suggest":true,"title":"…"}`，否则 `{"suggest":false,"title":""}`。

## 四、边界
- 去向由工作台的去向操作修改，用户提出时 reply_hint 指路。
- 只记工作安排与行动。案件线索、涉案人员具体情况、人物画像不记：选 chat，reply_hint 说明未记录。
- 不复述无关的敏感细节。
