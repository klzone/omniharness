# 业务知识整理

## 一、用途

把用户提供或明确授权的长篇材料，整理成一卡一概念、可独立阅读、可回查来源的知识卡片。

## 二、触发与排除

- 触发：把制度、方案、总结、讲话纪要拆成知识卡；梳理多篇材料之间的政策脉络；对照新旧规定找变动点。
- 排除：只查已有知识卡（用 `knowledge-search`）；没有授权材料时凭空建卡；案件材料、线索、人物画像。

## 三、材料与事实

- 只用用户提供或明确授权的公开法规、内部制度、脱敏材料；不声称读过未提供的文件。
- 材料里的定义、条款、数字原样使用；自己的归纳、推断与经验另起一句，并标「待核实」。
- 多份材料口径冲突时并列指出，不挑一个当对的；缺出处就写「来源未给出」。
- 案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进入整理；遇到即停止并说明。

## 四、整理口径

先定「这张卡回答什么问题」，再写定义与展开；不把一段材料机械切片。
- 一张卡只回答一个问题；两个问题就拆两张。
- 正文先写一句话定义，再写不看别的卡也能懂的要点，最后列相关卡片。
- 外部依据写进 `sources`；自己的判断、经验、推断在正文标「待核实」。
- 卡片之间的双链只指向已存在或本批会创建的标题。

## 五、长度与拆分

- 单卡正文不超过 320 字（不含 frontmatter）；超过 320 字必须拆成多张卡。
- 拆分标题统一用「原标题（上）/（中）/（下）」；每张卡保留独立 title、路径、索引行与 sources，索引行用「参见」互相链接。
- 拆出的每张卡正文同样 ≤320 字；长文按主题段先拆再压，不允许拆完仍超。
- 宿主只在单卡超过 420 字时拒收；拆卡由模型完成，宿主不做强行切分。

## 六、写卡与边界

写卡、暂存、同步索引按 `knowledge-search` 的流程执行：先查索引防重复，只写暂存区，落库与索引行由宿主完成，不直接写知识库根。
未收录就写未收录；不把「应该如此」写成「制度规定」；身份证号、手机号按 Profile 规则资产掩码。
