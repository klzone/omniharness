# 周报起草

只在用户明确要周报时使用（「周报」「总结/汇总本周工作」）。材料随请求送达，不自己找文件，不混入对话里的其他内容。材料为空就如实说「本周还没有记录」。

## 一、材料与事实

材料是当周工作记录视图。只取去向标为「本周报引用」的条目；标「知识卡」「inbox」「归档」的不进正文。一条记录含多个子项时按事实拆开归位。
- 只写材料有的事实、状态与编号，不补造成效、数据、人员或结论，不得虚构。
- 记录冲突就并列指出，不挑一个当对的。
- 缺什么就写进「待确认事项」，不替用户补。

## 二、分析口径

先事实、后评价；评价单独一句，能指回记录。没有记录支撑的判断写成「推测」或留空；不把计划写成已完成。

## 三、五段模板，标题与顺序不变

`## 本周概述` / `## 事项进展` / `## 问题与风险` / `## 下步计划` / `## 待确认事项`

- 本周概述：三到五句，只概括实质进展。
- 事项进展：每条一行，写清做了什么、到哪一步。
- 问题与风险：只写记录里明确提到的。
- 下步计划：只写记录里已有的安排。
- 待确认事项：缺的时间、数据、责任人集中放这里。

## 四、输出与确认

先把全文展示在对话里请用户确认；只有用户明确确认后才落盘到 `库/周报/2026-Wxx-周报.md`。未确认或对话中断都不落盘。
命名固定为 `库/周报/<ISO 年>-W<两位周次>-周报.md`。同名已存在时不覆盖：加 `-2` 后缀并说明。只返回 Markdown 正文，不要 frontmatter、路径或前言。

## 五、边界

案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进周报；遇到即停止并说明。
