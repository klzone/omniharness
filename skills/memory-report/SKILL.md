# 周报起草 (Memory Report)

只有用户明确要周报时才走这里：说「周报」，或说「总结/汇总本周工作」。工作台已经把当周工作记录作为材料交给你；材料为空就如实说「本周还没有记录」，不要凭空写。

## 一、取数：只取标记为本周报引用的条目

材料是当周 `库/工作记录/2026-Wxx.md` 的原文。只取 `去向` 标为 `本周报引用` 的条目；
标了 `知识卡`/`inbox`/`归档` 的不进正文。一条记载有多个子项时，按事实拆开归位，不新增内容。

## 二、模板：五段，缺就写待确认

`本周概述` / `事项进展` / `问题与风险` / `下步计划` / `待确认事项`

- 本周概述：三到五句，只概括高量级的实质进展；
- 事项进展：每条一行，写清做了什么、到哪一步；
- 问题与风险：记录里明确提到的问题才写；
- 下步计划：只写记录里已有的下一步；
- 待确认事项：记录缺的时间、数据、责任人等集中放这里。

只写记录里有的事实。**不得补造**成效、数据、人员或结论。事实之间有冲突就并列指出，不挑一个当对的。

## 三、确认：先展示，后落盘

1. **把全文展示在对话里**，请用户确认或修改。此时**没有写任何文件**。
2. **只有用户明确确认后才落盘**到 `库/周报/2026-Wxx-周报.md`。
   未确认、只说「再改改」、或对话中断，都保持不落盘。
3. 落盘走工作台的待确认写入，不自行覆盖。

命名写死：`库/周报/<ISO 年>-W<两位周次>-周报.md`，如 `2026-W43-周报.md`。
同名已存在时**不覆盖**：加 `-2` 后缀并说明，或由用户决定。

## 四、数据边界

案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进周报；遇到即停止并说明。

## 五、自检

正文是否只来自 `本周报引用`？有没有补造？是不是先展示、用户确认之后才落盘？同名文件有没有被覆盖？
