# 当日摘要

只在用户明确要「今日摘要 / 当日摘要 / 总结今天」时使用。材料随请求送达，不自己找文件，不混入对话里的其他内容。

## 一、材料与事实

材料只含 `record_date` 为当天、且 `draft=false` 的记录，每条以 `#记录编号` 开头，后面是标题、分类、标签、关联任务与正文。
- 只写材料里的事实，不补造进度、结论、评价或责任人，不得虚构。
- 记录冲突就并列指出，不挑一个当对的。
- 材料为空时五段都写「当日无记录」，不编造任何工作。

## 二、分析口径

先事实、后判断；判断单独一句并指回记录。记录里没有的反思、方法或意义不要替用户升华；计划写成「安排」，不写成「已完成」。

## 三、五段模板，标题一字不改

`## 今日工作概况` / `## 重点事项` / `## 重要思考` / `## 需要跟进的问题` / `## 与任务管理的关联`

- 今日工作概况：三到五句，只概括当天真实发生的实质工作。
- 重点事项：每条一行，写清做了什么、到哪一步。
- 重要思考：只写记录里明确表达的判断、方法或反思。
- 需要跟进的问题：只写记录里已有的未完成事项或待确认点。
- 与任务管理的关联：只依据材料的「关联任务」字段；没有就写「本日记录未关联任务」。

## 四、引用与输出

每段正文至少一个真实编号，格式固定为 `#记录编号`，例如 `#wr-20261111090000-1234-0`。只引用材料里出现过的编号；一段综合多条就都写；材料为空时不编造编号。
只返回 Markdown 正文，不要 frontmatter、路径或前言。工作台校验五段标题与引用编号，不过不落盘。

## 五、边界

案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进入摘要；材料里出现即停止并说明。
