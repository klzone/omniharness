# 材料写作

## 一、用途

把用户提供的真实材料整理成结构完整、事实可回查、可人工审核的中文工作文稿初稿。

## 二、触发与排除

- 触发：写工作总结、汇报、调研报告、交流发言、理论心得；把零散记录合并成材料；按模板改写或压缩已有稿。
- 排除：纯格式转换；与内容无关的错别字修复；没有任何原始材料的凭空写作；单纯查资料（用 `knowledge-search` 或 `anysearch`）。

## 三、材料与依据

本技能目录下 `references/` 有三类资产：`templates/`（模板）、`writing-style/`（风格与避坑）、`excellent-cases/`（范例）。需要时实际读取对应文件；未读取的规则不得在交付里说成已核验。
- 依据顺序：用户本轮材料 > 用户指定模板 > 知识库同类历史材料。
- 只使用用户提供或明确选择的材料；不声称读过未提供的文件。
- 案件材料、线索、未公开审查调查信息、涉案人员、举报内容不进入处理；遇到即停止并说明。

## 四、写作口径

先定用途与受众，再定结构；先事实，后分析、判断与建议。四类内容分开：
- 事实：用户给出的时间、数量、事项、结果，原样使用，不改数、不合并；
- 分析：从事实能直接推出的因果或成效；
- 判断：审慎定性，证据不足就写「待确认」；
- 建议：对应前文问题或下步安排，不写成已完成。
没有依据的数据、成效、案例、责任人一律不补造；文风朴实，用「动词 + 数字 + 结果」，不用空泛套话。

## 五、输出契约

按下面四块输出，标题不变：

```markdown
### 【结构（章节列表）】
- 一、...
- 二、...

### 【初稿正文】
（按结构完整呈现的正文）

### 【待确认事项】
- 缺失的数据、日期或冲突口径逐项列明；没有就写「（本次无待确认事项）」。

### 【事实来源】
- 列明实际使用的材料文件、段落或用户原话，不声称使用未读取的文件。
```

## 六、质量清单与失败处理

清单：结构服务用途；每条事实能指回材料；没有材料未支持的结论；数字与原文一致；模板各段齐全；待确认项没有混进正文。
材料缺失、来源冲突或用户要求与材料矛盾时，停止相关段落，说明缺什么、冲突在哪，由用户决定后续；不硬凑、不越权。

## 七、按需加载

要查工作台知识卡读 `knowledge-search`，要联网核对公开信息读 `anysearch`，要成稿审校读 `document-review`。起草的底线只有本技能，其余按需。
